# 프로토타입 이슈 관리 기능 — 개요 및 설계 결정

## 목표

각 프로토타입에 대한 이슈(버그, 기능 요청 등)를 칸반 보드로 관리할 수 있는 기능 추가.  
기존 업무 관리(Task) 기능의 구조를 최대한 재활용한다.

---

## 핵심 설계 결정

### 1. 이슈 상태 (4단계)
| 코드 | 한글 | 설명 |
|------|------|------|
| `OPEN` | 이슈 등록 | 새로 등록된 이슈 |
| `IN_PROGRESS` | 해결 진행 | 담당자가 해결 중 |
| `TESTING` | 테스트 | 해결 후 검증 단계 |
| `CLOSED` | 완료 | 이슈 종결 |

### 2. 이슈 타입
| 코드 | 한글 |
|------|------|
| `BUG` | 버그 |
| `FEATURE` | 기능 요청 |
| `IMPROVEMENT` | 개선 |
| `QUESTION` | 질문 |
| `OTHER` | 기타 |

### 3. 우선순위
Task 관리와 동일: `LOW` / `MEDIUM` / `HIGH` / `URGENT`

### 4. 진입점 & URL 구조
- 프로토타입 상세 페이지(`PrototypeDetailPage`) 우측 버튼 영역에 **"이슈 관리"** 버튼 추가
- 클릭 시 `/issues?prototypeId=xxx` 페이지로 이동 (docu 페이지 패턴과 동일)
- 라우터에 `/issues` 라우트 추가 (`validateSearch`로 prototypeId 검증)

### 5. UI 구성
- 기본 뷰: **칸반 보드** (상태별 4개 칼럼)
- 전환 뷰: **테이블 뷰**
- 이슈 생성/상세: **다이얼로그** (Task 패턴 동일)
- 댓글 기능: 포함
- 담당자 지정: 포함

### 6. 권한
- 이슈 생성: 로그인 사용자 모두 가능
- 이슈 수정/삭제: admin 또는 reporterId
- 댓글 수정/삭제: admin 또는 댓글 작성자
