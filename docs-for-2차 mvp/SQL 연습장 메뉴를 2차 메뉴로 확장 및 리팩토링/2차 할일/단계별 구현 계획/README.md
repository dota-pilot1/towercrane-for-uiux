# SQL 연습장(유저) 단계별 구현 계획

## 구현 원칙

1차 MVP는 파일 업로드 없이 진행한다.

`SQL 연습장(유저)`는 하나의 커머스 운영 DB를 기준으로 문제를 만들고 푸는 공간으로 구현한다. DB 파일을 여러 개 다루기보다 `스키마 버전 + 문제 + 제출` 구조를 먼저 안정화한다.

추후 유저나 관리자가 sqlite 파일 자체를 교체하는 기능은 열어둘 수 있다. 사용자 경험상으로는 현재 파일을 덮어쓰는 동작으로 제공하되, 내부적으로는 기존 schema version을 보존하고 새 version을 활성화한다.

## 우선순위

MVP에서 가장 먼저 검증할 것은 “유저가 문제를 만들고 다른 유저가 풀 수 있는가”이다.

따라서 구현 우선순위는 다음과 같다.

```text
기본 DB 준비
→ 문제 CRUD
→ 문제 목록/풀이 UI
→ 제출 저장
→ 기본 채점
→ 스키마 변경
```

sqlite 파일 업로드, 여러 연습장 생성, 공개/비공개 연습장, 문제 신고/검수는 MVP 이후로 미룬다.

파일 교체 기능은 `스키마 변경` 단계 이후에 붙인다. 교체된 파일은 새 schema version으로 등록하고, 기존 문제/제출은 기존 version에 그대로 보존한다.
