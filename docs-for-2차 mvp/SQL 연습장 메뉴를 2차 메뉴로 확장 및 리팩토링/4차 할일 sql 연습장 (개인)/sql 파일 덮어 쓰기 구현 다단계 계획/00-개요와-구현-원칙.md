# 00. 개요와 구현 원칙

## 목표

`/sql/personal` 오른쪽 테이블 패널의 `ERD` 버튼 왼쪽에 `SQL 교체` 버튼을 추가한다.

버튼을 누르면 다이어로그가 열리고, 로그인한 사용자가 `.sql` 파일을 업로드해 개인 SQL 연습장의 기준 DB를 교체할 수 있게 한다.

## 중요한 표현 정리

사용자 관점에서는 "SQL 파일 덮어쓰기"처럼 보인다.

시스템 관점에서는 기존 row를 덮어쓰지 않는다. 새 `schema version`을 만들고 workspace의 `active_schema_version_id`만 새 버전으로 바꾼다.

## 왜 다단계가 필요한가

이 기능은 버튼 하나가 아니라 다음 영역을 같이 건드린다.

- multipart 업로드
- SQL 파일 안전 검증
- 임시 DB 생성 및 introspection
- metadata DB에 schema version 생성
- active schema version 교체
- 기존 문제/공유 링크 보존
- 프론트 FormData 처리
- react-query invalidate
- 업로드 다이어로그 UI

한 파일에서 한번에 구현하면 실패 원인 추적이 어렵다. 따라서 아래 단계로 나눠 구현한다.

## 핵심 원칙

```text
기존 schema version은 수정하지 않는다.
파일 교체는 새 schema version을 만든다.
workspace active schema version만 새 버전으로 바꾼다.
기존 문제와 공유 링크는 기존 schema version을 계속 참조한다.
새 문제는 새 active schema version에 묶인다.
```

## MVP 범위

포함:

- `.sql` 파일 업로드
- SQL 파일 검증
- 새 schema version 생성
- active schema version 교체
- 테이블 목록/row count 갱신
- 문제 생성 기준 DB 변경

제외:

- `.sqlite`, `.db` 직접 업로드
- ERD 자동 생성
- version history 화면
- 이전 version 재활성화 UI
- 기존 문제를 새 DB로 마이그레이션
- 기존 공유 링크의 schema version 변경

## 완료 기준

1. 개인 SQL 연습장 오른쪽 테이블 패널에 `SQL 교체` 버튼이 보인다.
2. 버튼은 `ERD` 버튼 왼쪽에 있고 높이가 같다.
3. `.sql` 파일을 업로드하면 새 schema version이 생성된다.
4. 화면의 schema version/hash/tables가 새 파일 기준으로 갱신된다.
5. 새 문제는 새 schema version 기준으로 생성된다.
6. 기존 문제와 기존 공유 링크는 이전 schema version 기준으로 계속 동작한다.
