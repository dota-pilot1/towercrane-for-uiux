## 구현 순서

1. 백엔드 endpoint와 service를 먼저 만든다.
2. 서버 빌드로 타입을 잡는다.
3. 프론트 `apiRequest` FormData 처리를 보강한다.
4. 프론트 API/mutation을 추가한다.
5. 업로드 다이어로그를 만든다.
6. `/sql/personal` 오른쪽 테이블 패널에 `SQL 교체` 버튼을 연결한다.
7. 실제 `.sql` 업로드로 검증한다.

## 구현 판단

다단계가 필요하다.

이유는 이 기능이 단순 UI 버튼이 아니라 schema version 도메인 변경을 포함하기 때문이다. 기존 문제/공유 링크 보존을 깨지 않으려면 백엔드 metadata, runtime DB, 프론트 query 갱신을 순서대로 확인해야 한다.
