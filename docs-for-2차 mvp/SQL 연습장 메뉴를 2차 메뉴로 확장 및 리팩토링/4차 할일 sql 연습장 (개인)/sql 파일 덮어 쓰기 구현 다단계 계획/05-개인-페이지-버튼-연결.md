# 05. 개인 페이지 버튼 연결

## 목표

`/sql/personal` 오른쪽 테이블 패널의 `ERD` 버튼 왼쪽에 `SQL 교체` 버튼을 추가하고 업로드 다이어로그와 연결한다.

## 대상 파일

```text
towercrane-for-uiux-front/src/pages/sql-practice/ui/sql-user-practice-page.tsx
```

## 표시 위치

`SqlPersonalPracticeWorkspace`의 오른쪽 테이블 패널 header:

```tsx
<div className="flex items-center gap-2">
  <button>SQL 교체</button>
  <button>ERD</button>
</div>
```

현재 구조에서 `ERD` 버튼 렌더링 위치의 왼쪽에 넣는다.

## 버튼 조건

보이는 곳:

- `/sql/personal`

보이지 않는 곳:

- `/sql/user`
- `/share/sql/personal/:token`

## 버튼 스타일

ERD 버튼과 높이를 맞춘다.

```tsx
className="ui-icon-button h-8 gap-1.5 px-3 text-xs"
```

아이콘:

- `Upload`
- 또는 `FileUp`

## 상태 추가

```ts
const [replaceSqlOpen, setReplaceSqlOpen] = useState(false)
const [replaceSqlError, setReplaceSqlError] = useState<string | null>(null)
```

mutation:

```ts
const replaceSchemaMutation = useReplaceSqlPersonalPracticeSchemaVersion(workspaceId)
```

## submit 처리

```ts
const handleReplaceSchema = async (input) => {
  setReplaceSqlError(null)
  try {
    await replaceSchemaMutation.mutateAsync(input)
    setReplaceSqlOpen(false)
    setSelectedProblemId(null)
    setSelectedTable(null)
    setLastResult(null)
    setGradeResult(null)
    handleRefresh()
  } catch (error) {
    setReplaceSqlError(error instanceof Error ? error.message : 'SQL 파일 교체에 실패했습니다.')
  }
}
```

## 성공 후 UX

교체 성공 시:

- 다이어로그 닫기
- 오른쪽 테이블 목록 새 DB 기준으로 갱신
- schema 표시 `v2`로 갱신
- hash 갱신
- 선택된 문제 해제
- 실행 결과 초기화

선택된 문제를 유지하지 않는 이유:

- 기존 문제는 이전 schema version에 묶여 있을 수 있다.
- active schema version 교체 직후에는 새 문제 생성/새 테이블 확인 흐름이 우선이다.
