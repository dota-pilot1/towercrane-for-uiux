# 개인 공유 풀이 유저별 정답 체크 구현 계획

## 목표

개인 SQL 연습장을 공유받은 사용자가 문제를 풀면, 공식 SQL 연습장처럼 로그인 유저별 풀이 상태를 저장하고 왼쪽 문제 목록에 정답/오답 상태를 표시한다.

## 현재 문제

- 개인 SQL 연습장 채점은 결과만 반환하고 제출 기록을 저장하지 않는다.
- 공유 링크(`/share/sql/personal/:token`)는 public API라 로그인 유저 정보가 채점 API에 전달되지 않는다.
- 왼쪽 사이드바의 아이콘은 공유 여부 표시라서, 정답 체크처럼 보일 수 있다.

## 구현 단계

1. DB 테이블 추가
   - `sql_personal_practice_submissions`
   - `user_id`, `problem_id`, `workspace_id`, `schema_version_id`, `share_id`, `submitted_sql`, `answer_sql`, `is_correct`, `score`, `max_score`, `feedback`, `created_at`
   - 운영 SQLite는 `CREATE TABLE IF NOT EXISTS` 방식으로 앱 재시작 시 자동 보정한다.

2. 백엔드 채점 저장
   - 개인 페이지 채점: 로그인 유저 기준 저장
   - 공유 페이지 채점: Authorization 토큰이 있으면 해당 유저 기준 저장
   - 비로그인 공유 풀이: 기존처럼 채점만 하고 저장하지 않는다.

3. 상태 조회 응답 확장
   - 개인 문제 목록에 `submissionStatus` 포함
   - 공유 문제 조회 응답에 현재 로그인 유저의 `submissionStatus` 포함
   - 상태는 문제별 최고 점수/마지막 제출 기준으로 계산한다.

4. 프론트 API 수정
   - 공유 개인 문제 API에서 로그인 토큰이 있으면 Authorization 헤더가 전송되도록 `skipAuth`를 제거한다.
   - 채점 성공 후 개인 문제 목록/공유 문제 query를 invalidate한다.

5. UI 수정
   - 개인 페이지 왼쪽 사이드바:
     - 정답: 체크 아이콘
     - 오답 제출 있음: X 아이콘
     - 미제출: 표시 없음
     - 공유 여부는 텍스트/작은 링크 아이콘으로 분리
   - 공유 페이지 왼쪽 사이드바도 같은 규칙 적용

## 정책

- 유저별 기록은 로그인 유저에게만 저장한다.
- 공유자와 풀이자는 같은 테이블을 쓰되 `user_id`로 분리한다.
- 공유 링크가 해제되어도 기존 제출 기록은 삭제하지 않는다.
- SQL 파일 교체 후 기존 문제/공유는 기존 `schema_version_id` 기준으로 채점한다.
