# 03. 프론트 데이터 계층 계획

## 목표

`/sql/user`, `/sql/personal/workspaces/:workspaceId`, `/share/sql/personal/:token`에서 필요한 API와 query hook을 명확히 분리한다.

## 변경 파일

### `towercrane-for-uiux-front/src/entities/sql-practice/model/types.ts`

개인 도메인 타입 추가:

```ts

```

공개 응답 타입 추가:

```ts
export type SqlPersonalPracticePublicProblem = Omit<
  SqlPersonalPracticeProblem,
  'answerSql'
>

export type SqlPersonalPracticePublicProblemResponse = {
  workspace: Pick<SqlPersonalPracticeWorkspace, 'id' | 'title'>
  schemaVersion: Pick<
    SqlPersonalPracticeSchemaVersion,
    'id' | 'version' | 'title' | 'dbFileHash'
  >
  problem: SqlPersonalPracticePublicProblem
  tables: TableInfo[]
  erdMmd: string | null

```

공유 mutation 응답 타입:

```ts

  id: string
  problemId: string

  schemaVersionId: string

```

shareUrl은 서버가 만들지 않고 프론트에서 `window.location.origin`으로 만든다.

```ts

  { skipAuth: true },
)
```

### `towercrane-for-uiux-front/src/features/sql-practice/model/use-sql-practice-queries.ts`

query key 추가:

```ts
personalWorkspaces: ['sql-practice', 'personal', 'workspaces'] as const,
personalDefaultWorkspace: ['sql-practice', 'personal', 'workspaces', 'default'] as const,
personalWorkspaceMeta: (workspaceId: string) =>
  ['sql-practice', 'personal', 'workspace', workspaceId, 'meta'] as const,
personalTables: (workspaceId: string) =>
  ['sql-practice', 'personal', 'workspace', workspaceId, 'tables'] as const,
personalProblems: (workspaceId: string, filter?: { level?: number }) =>
  ['sql-practice', 'personal', 'workspace', workspaceId, 'problems', filter ?? {}] as const,
personalProblem: (workspaceId: string, id: string) =>
  ['sql-practice', 'personal', 'workspace', workspaceId, 'problem', id] as const,
publicPersonalProblem: (token: string) =>
  ['sql-practice', 'public-personal', token] as const,
```

hook 추가:

```ts
useSqlPersonalDefaultWorkspace()
useSqlPersonalPracticeProblems(workspaceId, filter)
useSqlPersonalPracticeProblem(workspaceId, id)
useCreateSqlPersonalPracticeProblem(workspaceId)
useUpdateSqlPersonalPracticeProblem(workspaceId)
useDeleteSqlPersonalPracticeProblem(workspaceId)
useShareSqlPersonalPracticeProblem(workspaceId)
useUnshareSqlPersonalPracticeProblem(workspaceId)
useGenerateSqlPersonalPracticeAnswer(workspaceId)
useGradeSqlPersonalPracticeProblem(workspaceId)
usePublicSqlPersonalPracticeProblem(token)
useGradePublicSqlPersonalPracticeProblem()
```

invalidate 규칙:

- create/update/delete/share/unshare 성공: 해당 workspace의 `personalProblems` invalidate
- 단일 문제 update/share/unshare 성공: `personalProblem(workspaceId, id)` invalidate
- 파일 교체 후속 구현: `personalWorkspaceMeta`, `personalTables`, `personalProblems` invalidate
- 공개 풀이 grade 성공: 공개 문제 query는 invalidate하지 않아도 된다.

toast 문구:

- 생성: `개인 문제를 등록했습니다.`
- 공유: `공유 링크를 만들었습니다.`
- 공유 해제: `공유 링크를 해제했습니다.`
- 삭제: `개인 문제를 삭제했습니다.`

## 기존 user query 영향

기존 `userProblems` query key는 그대로 둔다.

개인 문제는 별도 API와 별도 테이블을 쓰므로 `/sql/user` 목록에 섞이지 않는다.
