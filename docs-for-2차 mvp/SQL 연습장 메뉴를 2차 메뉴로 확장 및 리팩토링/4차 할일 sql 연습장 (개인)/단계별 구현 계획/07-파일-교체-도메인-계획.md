# 07. 파일 교체 도메인 계획

## 목표

`SQL 연습장(개인)` 이후 사용자가 개인 연습장의 SQL 파일 또는 sqlite 파일을 교체할 수 있게 한다.

파일 교체는 기존 문제를 덮어쓰는 작업이 아니다. 새 schema version을 만들고 active version만 바꾸는 작업이다.

## 핵심 원칙

```text
문제는 생성 당시 schema version에 고정된다.
공유 링크도 생성 당시 schema version에 고정된다.
파일 교체는 새 schema version을 만들 뿐, 기존 version을 삭제하지 않는다.
```

이 원칙이 없으면 파일 교체 후 다음 문제가 생긴다.

- 기존 문제의 `targetTables`가 사라짐
- 기존 `answerSql`이 실행되지 않음
- 이미 공유한 링크의 정답 기준이 바뀜
- 다른 사람이 풀던 링크가 갑자기 깨짐

## 추가 API

MVP 이후 단계에서 추가한다.

```text
GET  /sql/personal/workspaces/:workspaceId/schema-versions
POST /sql/personal/workspaces/:workspaceId/schema-versions
POST /sql/personal/workspaces/:workspaceId/schema-versions/:versionId/activate
GET  /sql/personal/workspaces/:workspaceId/schema-versions/:versionId/tables
GET  /sql/personal/workspaces/:workspaceId/schema-versions/:versionId/erd
```

업로드 방식:

```text
POST /sql/personal/workspaces/:workspaceId/schema-versions
Content-Type: multipart/form-data
file: .sql 또는 .sqlite
title: string
description?: string
```

초기 구현은 `.sql`만 허용하고, sqlite 파일은 후속으로 미뤄도 된다.

## 서비스 동작

### SQL 파일 업로드

1. owner 권한 확인
2. 파일 확장자와 크기 제한 확인
3. SQL safety 검사
4. 임시 runtime DB에 적용
5. 테이블 목록/컬럼 introspection
6. schema hash 계산
7. 새 `sql_personal_practice_schema_versions` row 생성
8. workspace `active_schema_version_id` 갱신

### sqlite 파일 업로드

sqlite는 SQL 파일보다 위험도가 높다.

검증 항목:

- 실제 SQLite database인지 확인
- 파일 크기 제한
- 시스템 테이블 제외
- attach, extension, virtual table 등 위험 요소 제한
- introspection 가능 여부 확인

sqlite 업로드는 MVP 이후로 분리하는 것을 권장한다.

## 문제 생성 규칙

파일 교체 후 새 문제를 만들면 새 active schema version에 묶인다.

```text
문제 A: schema version 1
파일 교체: schema version 2 active
문제 B: schema version 2
```

문제 A는 계속 version 1 DB에서 채점한다. 문제 B는 version 2 DB에서 채점한다.

## 공유 링크 규칙

공유 생성 시 share row에 `schema_version_id`를 저장한다.

```text
share token abc
  problemId: 문제 A
  schemaVersionId: version 1
```

파일을 교체해 version 2가 active가 되어도 token `abc`는 version 1 기준으로 계속 동작한다.

## 프론트 화면

### `/sql/personal`

기본 개인 workspace로 진입한다.

### `/sql/personal/workspaces/:workspaceId`

문제 목록과 풀이 UI를 보여준다.

상단에 현재 active schema version을 표시한다.

```text
개인 커머스 DB · v2 · 12 tables · hash abc123
```

### `/sql/personal/workspaces/:workspaceId/files`

파일 관리 화면이다.

기능:

- 현재 active version 표시
- version history 표시
- SQL 파일 업로드
- 특정 version 다시 활성화
- version별 테이블 보기

## 검증

1. version 1에서 문제 생성
2. 공유 링크 생성
3. 파일 교체로 version 2 생성
4. version 2에서 새 문제 생성
5. version 1 공유 링크가 계속 version 1 기준으로 채점되는지 확인
6. version 2 문제는 version 2 테이블 기준으로 채점되는지 확인
7. version 1을 삭제하지 않는지 확인

## 보류 항목

- schema version 삭제
- 기존 문제를 새 schema version으로 마이그레이션
- 문제별 schema version 변경
- 공개 풀이 로그 저장
