# 05. 공개 공유 풀이 페이지 계획

## 목표

공유 링크를 받은 사람이 로그인 없이 개인 SQL 문제를 풀 수 있게 한다.

## URL

```text
/share/sql/personal/:token
```

프론트 라우트는 AppLayout auth guard 밖에 둔다.

## 변경 파일

### `towercrane-for-uiux-front/src/app/router.tsx`

공개 페이지 import:

```ts
import { SqlPublicPersonalPracticePage } from '../pages/sql-practice/ui/sql-public-personal-practice-page'
```

라우트 추가:

```ts
const publicSqlPersonalPracticeRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/share/sql/personal/$token',
  component: SqlPublicPersonalPracticePage,
})
```

routeTree에 `publicSqlPersonalPracticeRoute`를 `loginRoute`, `publicSqlNoteRoute`와 같은 레벨로 추가한다.

### 신규 파일: `towercrane-for-uiux-front/src/pages/sql-practice/ui/sql-public-personal-practice-page.tsx`

역할:

- token param 읽기
- `usePublicSqlPersonalPracticeProblem(token)` 호출
- 문제 설명/대상 테이블/SQL 입력/실행 결과/채점 피드백 표시
- 응답의 `schemaVersion`을 표시하고, 풀이/채점은 해당 version 기준임을 유지
- 로그인 버튼 또는 콘솔 이동 버튼은 보조 액션으로만 제공

공개 페이지 구성:

```text
상단: Towercrane Console / SQL 공유 문제 / schema vN
본문 좌측: 문제 설명 + 답안 SQL 입력 + 실행/채점 결과
본문 우측: 테이블 목록 + ERD 버튼
```

공개 페이지에서는 문제 생성/수정/삭제/공유 버튼이 없다.

공개 응답의 `problem.answerSql`은 내려오지 않으므로 정답 SQL 노출 위험이 없다.

### 재사용 컴포넌트

가능하면 아래 기존 컴포넌트를 재사용한다.

- `SqlResultTable`
- `SqlTableSchemaDialog`
- `SqlErdDialog`

`SqlUserPracticeGradeDialog`는 answerSql 노출 없이 피드백 중심으로 쓸 수 있으면 재사용한다. 아니면 공개 전용 `SqlPublicPracticeGradeResult`를 만든다.

### `towercrane-for-uiux-front/src/entities/sql-practice/api/sql-practice-api.ts`

공개 조회:

```ts
getPublicPersonalProblem: (token: string) =>
  apiRequest<SqlPersonalPracticePublicProblemResponse>(
    `/public/sql/personal/${encodeURIComponent(token)}`,
    { skipAuth: true },
  )
```

공개 채점:

```ts
gradePublicPersonalProblem: (token: string, payload: SqlUserPracticeGradePayload) =>
  apiRequest<SqlUserPracticeGradeResponse>(
    `/public/sql/personal/${encodeURIComponent(token)}/grade`,
    {
      method: 'POST',
      body: JSON.stringify(payload),
      skipAuth: true,
    },
  )
```

## 공개 풀이 보안 규칙

- 공개 조회 응답에 `answerSql`을 포함하지 않는다.
- 제출 SQL은 SELECT/WITH만 허용한다.
- 공개 풀이 runtime DB는 token + schemaVersion 기준으로 분리한다.
- 공유 해제된 token은 즉시 404가 되어야 한다.
- draft/archived 문제는 공유 token이 있어도 공개 접근을 막는다.
- 파일 교체 후에도 기존 token은 share에 저장된 schemaVersion 기준으로 채점되어야 한다.
- CORS나 auth header가 없어도 공개 API가 동작해야 한다.

## 링크 생성 규칙

프론트에서 공유 링크를 만들 때:

```ts
const url = `${window.location.origin}/share/sql/personal/${share.token}`
```

개인 문제 상세에는 다음 액션을 모두 둔다.

```text
공유 링크 만들기
링크 복사
공유 해제
```

복사 성공 toast:

```text
공유 링크를 복사했습니다.
```

token이 없으면 `링크 복사`가 먼저 share API를 호출한 뒤 링크를 만든다.
