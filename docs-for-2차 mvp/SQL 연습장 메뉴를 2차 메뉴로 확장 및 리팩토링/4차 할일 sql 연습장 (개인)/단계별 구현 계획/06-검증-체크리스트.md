# 06. 검증 체크리스트

## 백엔드 검증

### 타입/빌드

```bash
cd /Users/terecal/towercrane-for-uiux/towercrane-for-uiux-server
npm run build
```

### API 수동 검증

로그인 토큰이 있는 상태에서 확인한다.

1. 기본 workspace 생성/조회
   - `GET /sql/personal/workspaces/default`
   - workspace가 없으면 자동 생성
   - active schema version 1이 생성됨
   - 기본 schema version의 hash가 응답에 포함됨

2. 개인 문제 생성
   - `POST /sql/personal/workspaces/:workspaceId/problems`
   - 응답의 `workspaceId`가 요청 workspace와 같음
   - 응답의 `schemaVersionId`가 active schema version과 같음
   - `createdBy`가 현재 사용자

3. 개인 문제 목록
   - `GET /sql/personal/workspaces/:workspaceId/problems`
   - 해당 workspace의 개인 문제만 반환
   - 다른 사용자의 workspace 접근은 `403`

4. 유저 문제 목록 분리
   - `GET /sql/user/problems`
   - 기존 공용 유저 문제만 반환
   - 개인 도메인 문제가 섞이지 않음

5. owner 권한
   - 다른 사용자의 workspace/problem 수정/삭제/공유 시 `403`

6. 공유 링크 생성
   - `POST /sql/personal/workspaces/:workspaceId/problems/:id/share`
   - share token 생성
   - share row에 `problemId`, `workspaceId`, `schemaVersionId`가 저장됨
   - 두 번 호출해도 enabled share가 불필요하게 바뀌지 않음

7. 공유 링크 해제
   - `POST /sql/personal/workspaces/:workspaceId/problems/:id/unshare`
   - share `enabled = false`
   - 기존 공개 URL이 `404`

8. 공개 조회
   - `GET /public/sql/personal/:token`
   - 인증 없이 성공
   - 응답에 `answerSql` 없음
   - 응답에 `schemaVersion` 요약 있음

9. 공개 채점
   - `POST /public/sql/personal/:token/grade`
   - SELECT 정답 제출 시 정답 처리
   - DELETE/UPDATE/INSERT 제출 시 실패 처리
   - 채점 runtime DB가 token/schemaVersion 기준으로 분리됨

10. 파일 교체 대비
   - 문제 생성 후 active schema version을 바꾸는 상황을 가정해도 기존 문제의 `schemaVersionId`가 바뀌지 않음
   - share의 `schemaVersionId`가 문제 생성 당시 version을 유지함

## 프론트 검증

### 타입/빌드

```bash
cd /Users/terecal/towercrane-for-uiux/towercrane-for-uiux-front
npm run build
```

### 화면 검증

1. `/sql/user`
   - 기존 유저 연습장 화면이 정상 표시
   - 개인 문제가 목록에 노출되지 않음
   - 문제 풀이/채점 기존 동작 유지

2. `/sql/personal`
   - placeholder가 사라짐
   - 기본 workspace를 조회하거나 생성함
   - 개인 문제 관리 화면으로 진입함

3. `/sql/personal/workspaces/:workspaceId`
   - active schema version 표시
   - 내 개인 문제 목록만 표시
   - 문제 생성 가능
   - 문제 삭제 가능
   - 공유 링크 생성/복사 가능
   - 공유 token이 없는 상태에서 `링크 복사`를 눌러도 share 생성 후 공개 URL이 복사됨
   - 공유 해제 가능

4. `/share/sql/personal/:token`
   - 로그아웃 상태에서도 접근 가능
   - 문제 설명과 대상 테이블 표시
   - schema version 요약 표시
   - SQL 입력 후 실행/채점 가능
   - 정답 SQL은 화면에 노출되지 않음
   - 공유 해제 후 새로고침하면 접근 불가 화면 표시

## 회귀 리스크

- 개인 문제를 기존 `sql_user_practice_problems`에 섞어 저장하면 파일 교체 때 schema version 보존이 어렵다.
- 공개 API 응답에 `answerSql`이 포함되면 공유 페이지에서 정답이 노출된다.
- 공개 채점이 작성자 runtime DB를 사용하면 공개 풀이가 작성자 DB 상태를 오염시킬 수 있다.
- `/share/sql/personal/:token`을 AppLayout 아래에 넣으면 비로그인 사용자가 로그인으로 리다이렉트된다.
- 공유 링크가 schema version을 저장하지 않으면 파일 교체 후 기존 링크의 채점 기준이 바뀐다.

## 완료 기준

- 로그인 사용자는 `/sql/personal`에서 기본 개인 workspace를 사용할 수 있다.
- 개인 문제는 active schema version에 묶여 생성된다.
- 개인 문제는 `/sql/user` 목록에 보이지 않는다.
- 공유 링크를 받은 비로그인 사용자는 문제를 풀 수 있다.
- 공유 해제 즉시 공개 링크가 막힌다.
- 파일 교체를 위한 schema version 도메인 경계가 DB/API 타입에 반영되어 있다.
- 서버/프론트 빌드가 통과한다.
- 새 프론트 코드가 raw Tailwind 팔레트 금지 규칙을 지킨다.
