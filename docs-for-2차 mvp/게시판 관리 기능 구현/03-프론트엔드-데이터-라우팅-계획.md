## 1. `entities/board/model/types.ts`

필수 타입:

```ts
export type BoardKind = 'NOTICE' | 'INQUIRY' | 'FAQ' | 'EVENT' | 'GENERAL'
export type BoardStatus = 'PUBLISHED' | 'HIDDEN' | 'DRAFT'

export interface BoardConfig {
  id: string
  code: string
  kind: BoardKind
  name: string
  description: string | null
  allowUserWrite: boolean
  allowComment: boolean
  isActive: boolean
  orderIdx: number
  createdAt: string
  updatedAt: string
}
```

`BoardSummary`, `BoardDetail`, `BoardComment`, request 타입도 함께 둔다.

## 2. `entities/board/api/board-api.ts`

`shared/api/http.ts`의 `apiRequest`만 사용한다.

```ts
export const boardApi = {
  listConfigs: () => apiRequest<BoardConfig[]>('/boards/configs'),
  list: (code: string, filters?: BoardFilters) => ...,
  detail: (code: string, boardId: string) => ...,
  create: (code: string, body: CreateBoardRequest) => ...,
  update: (code: string, boardId: string, body: UpdateBoardRequest) => ...,
  delete: (code: string, boardId: string) => ...,
  listComments: (code: string, boardId: string) => ...,
  createComment: (code: string, boardId: string, content: string) => ...,
}
```

관리자 API는 `admin-board-api.ts`, `board-config-api.ts`로 분리해도 된다. 규모가 커질 가능성이 높으므로 분리 권장.

## 3. `features/board/model/use-board-queries.ts`

TanStack Query key:

```ts
export const boardQueryKeys = {
  all: ['boards'] as const,
  configs: () => ['boards', 'configs'] as const,
  list: (code: string, filters: BoardFilters) => ['boards', 'list', code, filters] as const,
  detail: (code: string, boardId: string | null) => ['boards', 'detail', code, boardId] as const,
  comments: (code: string, boardId: string | null) => ['boards', 'comments', code, boardId] as const,
}
```

mutation:

- `useCreateBoard`
- `useUpdateBoard`
- `useDeleteBoard`
- `useCreateBoardComment`

성공 시 invalidate:

- create/delete/update: `boardQueryKeys.all`
- comment create: comments + detail + list

## 4. `app/router.tsx`

import 추가:

```ts
import { BoardHomePage } from '../pages/board/ui/board-home-page'
import { BoardListPage } from '../pages/board/ui/board-list-page'
import { BoardDetailPage } from '../pages/board/ui/board-detail-page'
```

라우트 추가:

```ts
const boardsHomeRoute = createRoute({
  getParentRoute: () => appLayoutRoute,
  path: '/boards',
  component: BoardHomePage,
})

const boardListRoute = createRoute({
  getParentRoute: () => appLayoutRoute,
  path: '/boards/$code',
  component: BoardListPage,
})

const boardDetailRoute = createRoute({
  getParentRoute: () => appLayoutRoute,
  path: '/boards/$code/$boardId',
  component: BoardDetailPage,
})
```

`routeTree`에 세 라우트를 추가한다.

## 5. `widgets/app-header/ui/app-header.tsx`

`sectionIdToPath`에 추가:

```ts
boards: '/boards',
board_notice: '/boards/notice',
board_inquiry: '/boards/inquiry',
admin_board_configs: '/admin/board-configs',
admin_boards: '/admin/boards',
```

`getSectionIdFromPath`에 추가:

```ts
if (pathname.startsWith('/boards/notice')) return 'board_notice'
if (pathname.startsWith('/boards/inquiry')) return 'board_inquiry'
if (pathname.startsWith('/boards')) return 'boards'
if (pathname.startsWith('/admin/board-configs')) return 'admin_board_configs'
if (pathname.startsWith('/admin/boards')) return 'admin_boards'
```

헤더는 이미 자식 메뉴를 `NavDropdown`으로 렌더링하므로 메뉴 seed만 맞으면 드롭다운 동작이 가능하다.

## 6. `database.service.ts` 메뉴 seed

신규 메뉴를 seed로 넣을지, 관리자 메뉴 화면에서 수동 생성할지 결정해야 한다.

MVP 권장:

- `게시판` 루트 메뉴: `sectionId='boards'`, icon `MessageSquareText`
- 자식 `공지사항`: `sectionId='board_notice'`, icon `Megaphone`
- 자식 `문의 게시판`: `sectionId='board_inquiry'`, icon `MessagesSquare`
- 관리자 자식 `게시판 설정`: `sectionId='admin_board_configs'`, `requiredRole='admin'`
- 관리자 자식 `게시글 관리`: `sectionId='admin_boards'`, `requiredRole='admin'`

기존 메뉴 관리가 있으므로 seed는 idempotent upsert로만 넣고, 관리자가 이후 숨김/정렬을 조정할 수 있게 한다.

## 사용자 화면 기준

`/boards`:

- 활성 게시판 카드 목록
- 공지/문의뿐 아니라 새로 추가한 게시판도 자동 노출

`/boards/$code`:

- 게시판 제목/설명
- 핀 글 상단
- 최신순 목록
- `allowUserWrite`이면 새 글 버튼

`/boards/$code/$boardId`:

- 제목, 작성자, 작성일, 조회수
- 본인 글이면 수정/삭제
- `allowComment`이면 댓글/답변 영역
