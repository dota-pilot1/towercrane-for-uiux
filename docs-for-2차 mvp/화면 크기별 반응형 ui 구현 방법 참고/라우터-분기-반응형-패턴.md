# 화면 크기별 반응형 UI — 라우터 분기 패턴

> RestaurantBook 프로젝트(`/customer` 페이지)에서 검증된 구현 방식을 참고용으로 정리.

---

## 언제 이 패턴을 쓰나

Tailwind 반응형 클래스(`md:`, `lg:`)만으로는 **부족한** 경우에 사용한다.

| 상황 | 적합한 방법 |
|------|------------|
| 레이아웃만 달라지는 경우 (컬럼 수, 여백 등) | Tailwind 반응형 클래스로 충분 |
| UX 자체가 달라지는 경우 (터치 제스처, 캐러셀, 완전히 다른 정보 구조) | **라우터 분기 패턴** |
| 모바일 번들에 데스크탑 전용 코드 포함을 피하고 싶을 때 | **라우터 분기 패턴** |

---

## 구조 개요

```
/app/customer/
├── page.tsx          ← 데스크탑 진입점 + 모바일 감지 시 리다이렉트
└── mobile/
    └── page.tsx      ← 모바일 진입점

/features/kiosk/
├── KioskHome.tsx           ← variant prop으로 뷰 선택
├── ui/
│   ├── KioskDesktopView.tsx  ← 데스크탑 전용 UI
│   └── KioskMobileView.tsx   ← 모바일 전용 UI
└── model/
    └── useKioskOrder.ts      ← 공통 비즈니스 로직 (양쪽 공유)
```

## 핵심 코드

### 1. 데스크탑 페이지 — 모바일 감지 및 리다이렉트

```tsx
// app/customer/page.tsx
"use client";

import { useEffect } from "react";
import { useRouter } from "next/navigation";
import { KioskHome } from "@/features/kiosk/KioskHome";

export default function CustomerPage() {
  const router = useRouter();

  useEffect(() => {
    const mq = window.matchMedia("(max-width: 767px)");

    const check = () => {
      if (mq.matches) router.replace("/customer/mobile");
    };

    check(); // 최초 진입 시 즉시 평가
    mq.addEventListener("change", check); // 화면 크기 변경 시 재평가
    return () => mq.removeEventListener("change", check);
  }, [router]);

  return <KioskHome />;
}
```

**포인트:**
- `router.replace` (push 아님) → 뒤로가기 시 루프 방지
- `addEventListener("change", ...)` → 창 크기 조절에 실시간 반응

### 2. 모바일 페이지 — 단순 진입

```tsx
// app/customer/mobile/page.tsx
"use client";

import { KioskHome } from "@/features/kiosk/KioskHome";

export default function CustomerMobilePage() {
  return <KioskHome variant="mobile" />;
}
```

### 3. 공통 컴포넌트 — variant로 UI 분기

```tsx
// features/kiosk/KioskHome.tsx
"use client";

import { useKioskOrder } from "./model/useKioskOrder";
import { KioskDesktopView } from "./ui/KioskDesktopView";
import { KioskMobileView } from "./ui/KioskMobileView";

export function KioskHome({ variant = "desktop" }: { variant?: "desktop" | "mobile" }) {
  const kiosk = useKioskOrder(); // 비즈니스 로직은 한 곳에서만 관리

  if (variant === "mobile") return <KioskMobileView kiosk={kiosk} />;
  return <KioskDesktopView kiosk={kiosk} />;
}
```

**핵심 설계 원칙:**
- Hook(`useKioskOrder`)은 하나 — 데이터 페칭·상태 로직 중복 없음
- View 컴포넌트만 완전 분리 — 각자 최적화 자유

## 모바일 뷰 구현 특징 (KioskMobileView)

RestaurantBook의 모바일 뷰는 데스크탑과 완전히 다른 UX를 구현한다:

```tsx
// 터치 스와이프 제스처 (useMobileProductPager 훅)
const finishTouch = (clientX: number) => {
  if (touchStartX == null) return;
  const deltaX = clientX - touchStartX;
  setTouchStartX(null);
  if (Math.abs(deltaX) < 48) return; // 미세한 터치 무시
  moveProduct(deltaX < 0 ? 1 : -1);
};
```

- **단일 열 + 스크롤** 레이아웃 (데스크탑은 2단 그리드)
- **framer-motion** `AnimatePresence`로 카드 슬라이드 애니메이션
- **fixed 푸터**로 결제 버튼 항상 노출
- 최소 스와이프 거리(48px) 조건으로 의도하지 않은 제스처 차단

## 장단점

**장점**
- URL 자체가 디바이스 컨텍스트를 표현 → 명확, 디버깅 쉬움
- 모바일 번들에 데스크탑 코드 포함 안 됨 → 성능
- 비즈니스 로직 중복 없음 (hook 공유)
- 화면 크기 변경에 실시간 반응 (matchMedia change 이벤트)

**주의사항**
- `window.matchMedia`는 SSR 불가 → `"use client"` 필수, 최초 렌더 시 데스크탑 화면이 순간 노출될 수 있음
- SSR에서 flash를 완전히 없애려면 Next.js middleware + `user-agent` 헤더 감지 방식으로 교체 가능
- 모바일 사용자가 데스크탑 URL을 직접 열면 다시 리다이렉트됨 → 의도된 동작

## SSR 방식 (업그레이드 옵션)

flash 없는 서버 사이드 리다이렉트가 필요하면 middleware로 교체:

```ts
// middleware.ts
import { NextRequest, NextResponse } from "next/server";

export function middleware(req: NextRequest) {
  const ua = req.headers.get("user-agent") ?? "";
  const isMobile = /iPhone|Android|Mobile/i.test(ua);

  if (req.nextUrl.pathname === "/customer" && isMobile) {
    return NextResponse.redirect(new URL("/customer/mobile", req.url));
  }
}

export const config = { matcher: ["/customer"] };
```

단점: UA 문자열은 불확실하고 태블릿 판단이 어려움. 단순 리다이렉트 용도로만 사용 권장.
