## 라우트

추가:

- `/project-issues?projectId={projectId}`

라우터 search 검증:

- `projectId?: string`

구현:

```tsx
const ProjectIssuesRoute = createRoute({
  getParentRoute: () => RootRoute,
  path: '/project-issues',
  validateSearch: (search) => ({
    projectId: typeof search.projectId === 'string' ? search.projectId : undefined,
  }),
  component: ProjectIssuesPage,
})
```

## 페이지

`ProjectIssuesPage`:

```tsx
export function ProjectIssuesPage() {
  const { projectId } = useSearch({ strict: false }) as { projectId?: string }

  if (!projectId) {
    return <EmptyState message="프로젝트를 선택해주세요." />
  }

  return (
    <ProjectIssueWorkbench
      projectId={projectId}
      title="프로젝트 이슈"
      description="프로젝트 전체 이슈, 담당자, 체크리스트와 댓글을 관리합니다."
    />
  )
}
```

## 진입 버튼

프로젝트 단위 화면에서 `이슈 관리` 버튼을 추가한다.

버튼:

- 아이콘: `ShieldAlert` 또는 `ListTodo`
- 라벨: `이슈 관리`
- 이동: `/project-issues?projectId={project.id}`

프로토타입 상세의 기존 `이슈 관리` 버튼은 건드리지 않는다.

## 헤더 메뉴 노출 여부

MVP에서는 전역 헤더 메뉴에 `프로젝트 이슈`를 직접 추가하지 않는다.

이유:

- 프로젝트 이슈는 `projectId`가 있어야 의미가 있다.
- 전역 메뉴에서 들어가면 프로젝트 선택 UI가 추가로 필요하다.
- 현재는 프로젝트 문맥에서 진입하는 편이 자연스럽다.

후순위로 전체 프로젝트 이슈 통합 화면을 만들 때 전역 메뉴를 추가한다.

- `/project-issues/all`
- 전체 프로젝트 이슈 검색/필터
- project select 또는 project column 포함

## active section 처리

`/project-issues`가 어느 헤더 메뉴를 active로 잡을지는 실제 진입 위치에 맞춘다.

- 프로젝트 관리/Prototype 영역에서 진입하면 `prototype`
- 업무 관리 영역에서 진입하면 `task_group` 또는 `task_all`

MVP에서는 진입 버튼이 놓이는 메뉴 계열에 맞춰 `getSectionIdFromPath()`를 보정한다.

## 완료 조건

- `/project-issues?projectId=...` 새로고침 시에도 같은 화면이 열린다.
- `projectId` 없이 접근하면 선택 안내가 나온다.
- 기존 `/issues?prototypeId=...` 프로토타입 이슈 route가 그대로 동작한다.
- 프로젝트 진입 버튼과 프로토타입 이슈 버튼이 서로 다른 route로 이동한다.
