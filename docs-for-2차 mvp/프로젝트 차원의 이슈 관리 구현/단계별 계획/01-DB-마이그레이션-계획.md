## 원칙

기존 `issues`, `issue_comments`는 프로토타입 이슈 전용으로 유지한다.

프로젝트 이슈는 신규 테이블을 추가한다.

## `project_issues`

권장 컬럼:

- `id`: text primary key
- `projectId`: text not null
- `title`: text not null
- `content`: text not null default `''`
- `issueType`: `BUG` | `FEATURE` | `IMPROVEMENT` | `QUESTION` | `RISK` | `OTHER`
- `status`: `OPEN` | `IN_PROGRESS` | `TESTING` | `CLOSED` | `HOLD`
- `priority`: `LOW` | `MEDIUM` | `HIGH` | `URGENT`
- `reporterId`: users FK
- `assigneeId`: users FK nullable
- `dueDate`: text nullable
- `orderIdx`: integer default 0
- `archived`: boolean default false
- `createdAt`: text not null
- `updatedAt`: text not null

`projectId`는 MVP에서 현재 프로젝트 단위로 쓰는 id를 넣는다. 현재 별도 projects 테이블이 없다면 우선 `categoriesTable.id`를 참조한다. 추후 실제 `projects` 테이블이 생기면 FK만 이전한다.

## 데이터 마이그레이션

기존 프로토타입 이슈 데이터를 프로젝트 이슈로 옮기지 않는다.

프로젝트 이슈는 신규 기능이므로 seed가 필요하면 새 샘플 데이터만 넣는다.

샘플:

- 프로젝트 리스크 이슈 1개
- 기능 개선 이슈 1개
- 테스트/QA 이슈 1개

## 완료 조건

- 기존 `issues` 테이블이 그대로 동작한다.
- 새 `project_issues` 계열 테이블이 생성된다.
- 프로젝트별 목록 조회에 필요한 인덱스가 있다.
- 프로젝트 이슈 삭제 시 하위 댓글/체크리스트/첨부/activity가 cascade 된다.
