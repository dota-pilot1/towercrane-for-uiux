## UX 기준

프로젝트 이슈는 업무 관리와 거의 같은 흐름을 쓴다.

- 상단 PageHeader
- 검색/필터 toolbar
- 상태 카운트 filter bar
- 보관 보기 toggle
- 선택 보관/복원
- 테이블/칸반/카드 뷰 전환
- 페이지네이션
- 상세 다이얼로그 탭

다만 문구와 enum은 프로젝트 이슈 기준이다.

- 버튼: `새 이슈`
- 상태: `등록`, `진행`, `테스트`, `완료`, `보류`
- 유형: `버그`, `기능`, `개선`, `질문`, `리스크`, `기타`

## `ProjectIssueWorkbench`

역할:

- `projectId` 기준 필터 상태 관리
- 목록 query 호출
- create/detail dialog open 상태 관리
- view mode 관리
- pagination 관리
- bulk archive/restore 관리

예상 props:

```ts
type ProjectIssueWorkbenchProps = {
  projectId: string
  title?: string
  description?: string
}
```

## `ProjectIssueToolbar`

필터:

- 검색
- 이슈 유형
- 우선순위
- 담당자
- 정렬

상태 필터는 별도 카운트 bar에서 처리한다.

## `ProjectIssueDetailDialog`

탭:

- `개요`
- `체크리스트`
- `첨부`
- `댓글`
- `활동`

개요 필드:

- 제목
- 내용
- 유형
- 상태
- 우선순위
- 담당자
- 마감일

보관/복원 버튼은 업무 상세처럼 우상단에 둔다.

## 공통 컴포넌트 승격 기준

처음부터 `task`와 `project-issue`를 generic으로 묶지 않는다.

먼저 프로젝트 이슈 기능을 독립 구현하고, 아래 조합이 3회 이상 반복되면 `shared/ui/`로 올린다.

- 상태 카운트 필터 버튼
- 페이지네이션
- view mode segmented control
- 담당자 select
- priority select
- detail dialog 탭 레이아웃

## 스타일 규칙

반드시 semantic token 또는 `ui-*` 유틸을 사용한다.

금지:

- `text-white`
- `text-slate-*`
- `bg-white/*`
- `bg-slate-*`
- `border-white/*`
- `border-slate-*`
- `text-emerald-*`
- `bg-emerald-*`

권장:

- `text-text-primary`
- `text-text-secondary`
- `text-text-muted`
- `bg-surface-muted`
- `bg-surface-raised`
- `border-surface-border-soft`
- `bg-brand-glass`
- `text-brand-primary`
- `ui-panel`
- `ui-panel-soft`
- `ui-icon-button`

## 완료 조건

- 프로젝트 이슈 UI가 프로토타입 이슈 UI와 분리된다.
- 프로젝트 이슈 화면은 업무 관리와 동일하게 테이블/칸반/카드 뷰를 제공한다.
- detail dialog에서 체크리스트/첨부/댓글/activity가 모두 동작한다.
- raw Tailwind 팔레트 사용이 없다.
