## 스키마 변경

### `tasksTable`

추가 컬럼:

- `scope`: `TEAM` | `PERSONAL`, 기본값 `TEAM`
- `ownerId`: `users.id` FK, `onDelete: set null`
- `visibility`: `TEAM` | `PRIVATE`, 기본값 `TEAM`

권장 Drizzle 타입:

- `TaskScope = 'TEAM' | 'PERSONAL'`
- `TaskVisibility = 'TEAM' | 'PRIVATE'`

권장 인덱스:

- `idx_tasks_status_order`: `(status, order_idx)` 유지
- `idx_tasks_assignee_scope`: `(assignee_id, scope, archived, status)`
- `idx_tasks_owner_scope`: `(owner_id, scope, archived, status)`
- `idx_tasks_visibility_updated`: `(visibility, archived, updated_at)`

SQLite Drizzle에서 인덱스 선언을 바로 넣기 어렵거나 기존 패턴이 `database.service.ts`의 raw SQL 중심이면, `CREATE INDEX IF NOT EXISTS`를 `database.service.ts`에 먼저 반영한다.

## 데이터 삭제 허용 기준

개발 DB는 삭제 가능하므로 다음 중 하나로 진행한다.

### 권장: 전체 로컬 DB 초기화

1. 서버 중지.
2. 사용 중인 SQLite 파일 확인: `.env`의 `DATABASE_FILE` 또는 기본 `./data/towercrane-catalog.sqlite`.
3. SQLite 파일과 WAL/SHM 파일 삭제.
4. 서버 재시작으로 `database.service.ts`의 `CREATE TABLE IF NOT EXISTS`와 seed 실행.

주의: 테스트 계정이 필요하므로 `ensureDemoUser()`, `ensureTestUsers()`는 유지한다.

### 대안: 업무 테이블만 초기화

삭제 순서:

1. `task_activity_logs`
2. `task_attachments`
3. `task_comments`
4. `task_checklists`
5. `tasks`

그 다음 새 tasks schema 기준으로 재생성한다.

## 메뉴 seed 변경

현재 `업무 관리`는 단일 root menu다. 이를 다음 구조로 바꾼다.

- root: `업무 관리`, `section_id = task_group` 또는 `NULL`, `icon = CheckSquare`, `display_order = 3`
- child: `전체 업무`, `section_id = task_all`, `icon = ListChecks`, `display_order = 0`
- child: `내 업무`, `section_id = task_my`, `icon = UserCheck`, `display_order = 1`

기존 `section_id = 'task'` 메뉴가 있으면 중복을 막기 위해 다음 중 하나로 정리한다.

- 기존 메뉴를 root parent로 업데이트하고 child를 삽입.
- 또는 기존 `task` 메뉴를 삭제하고 새 구조를 삽입.

데이터 삭제가 허용되므로 개발 DB에서는 후자가 단순하다. 운영/공유 DB에는 idempotent update 방식으로 작성한다.

## 샘플 업무 seed

개인 업무 페이지 검증을 위해 seed 업무를 최소 3개 넣는다.

- 팀 업무 1개: `scope=TEAM`, `visibility=TEAM`, 담당자 A.
- 팀 업무 1개: `scope=TEAM`, `visibility=TEAM`, 담당자 B.
- 개인 업무 1개: `scope=PERSONAL`, `visibility=PRIVATE`, `ownerId=A`, `assigneeId=A`.

## 완료 조건

- DB 초기화 후 서버 시작 시 오류 없이 테이블이 생성된다.
- 메뉴 API가 업무 관리 parent와 2개 child를 반환한다.
- 기존 `/tasks` 목록 조회가 새 컬럼을 포함해 반환된다.
- 개인 업무 private row가 다른 사용자 전체 업무 목록에 노출되지 않는다.
