# 04. 검증/배포 계획

## 로컬 검증

### 백엔드

작업 디렉터리:

- `/Users/terecal/towercrane-for-uiux/towercrane-for-uiux-server`

명령:

```bash
pnpm lint:check
pnpm test
pnpm build
```

확인할 API:

- `GET /tasks?scope=all`
- `GET /tasks?scope=my`
- `GET /tasks?scope=user&userId={id}`
- `POST /tasks` with `scope=TEAM`
- `POST /tasks` with `scope=PERSONAL`
- private 개인 업무 detail 권한

### 프론트엔드

작업 디렉터리:

- `/Users/terecal/towercrane-for-uiux/towercrane-for-uiux-front`

명령:

```bash
pnpm typecheck
pnpm lint
pnpm build
```

브라우저 확인:

- `/task`: 전체 업무 페이지가 뜬다.
- `/task/my`: `{내 이름}의 업무` 페이지가 뜬다.
- `/task/users/{userId}`: 선택 사용자 업무 페이지가 뜬다.
- 업무 관리 헤더 메뉴가 2차 메뉴로 열린다.
- 모바일 메뉴에서도 전체 업무/내 업무가 이동된다.
- 새 업무 생성, 상태 변경, 담당자 변경, 보관/복원이 scope별로 동작한다.

## 데이터 초기화 검증

데이터 삭제 허용 기준이 있으므로 개발 DB에서는 초기화 후 다음만 보장한다.

- 로그인 가능한 기본 사용자 존재.
- 업무 관리 메뉴 parent/children 존재.
- 샘플 업무가 전체 업무/내 업무에 각각 다르게 보인다.

## 회귀 확인

- 기존 `/task` URL은 계속 동작해야 한다.
- 기존 업무 상세 dialog, 체크리스트, 댓글, 첨부, activity tab은 전체/내 업무 페이지 모두에서 동작해야 한다.
- 기존 담당자 필터는 전체 업무에서만 정상 노출된다.
- private 개인 업무가 전체 업무나 다른 사용자 업무 페이지에 노출되지 않아야 한다.

## 완료 기준

- 헤더에서 `업무 관리` 2차 메뉴가 보인다.
- `전체 업무`와 `내 업무`가 별도 URL로 동작한다.
- 내 업무 페이지는 현재 로그인 사용자의 업무만 보여준다.
- 특정 사용자 업무 페이지는 해당 사용자의 팀 담당 업무만 보여준다.
- 개인 private 업무는 본인 외 목록/detail에서 차단된다.
- 프론트 타입체크와 빌드가 통과한다.
- 백엔드 빌드가 통과한다.
