## API/hook

`task-api.ts`는 `TaskFilters` 타입만 확장하면 `toSearchParams()`가 새 query를 처리한다.

`use-task-queries.ts`는 구조 유지:

- `taskQueryKeys.list(filters)`가 scope별 캐시를 자동 분리한다.
- create/update 성공 시 `taskQueryKeys.all` invalidate 유지.

## 라우터

`router.tsx` 추가:

- `/task`: `TaskPage` 전체 업무 mode
- `/task/my`: `TaskPage` 내 업무 mode
- `/task/users/$userId`: `TaskPage` 특정 사용자 mode

구현 방식:

- `TaskAllRoute`: `<TaskPage scopeMode="all" />`
- `TaskMyRoute`: `<TaskPage scopeMode="my" />`
- `TaskUserRoute`: route param `userId`를 읽어 `<TaskPage scopeMode="user" targetUserId={userId} />`

## `TaskPage` 변경

props:

- `scopeMode: 'all' | 'my' | 'user'`
- `targetUserId?: string`

필터 초기값:

- all: `{ scope: 'all', archived: false, sort: 'order', page: 1, pageSize: 50 }`
- my: `{ scope: 'my', archived: false, sort: 'order', page: 1, pageSize: 50 }`
- user: `{ scope: 'user', userId: targetUserId, archived: false, sort: 'order', page: 1, pageSize: 50 }`

헤더:

- all: `전체 업무`, `프로젝트 전체 업무, 담당자, 체크리스트와 댓글을 관리합니다.`
- my: `{currentUserName}의 업무`, `내가 담당하거나 개인으로 등록한 업무를 관리합니다.`
- user: `{targetUserName}의 업무`, `선택한 담당자의 팀 업무를 확인합니다.`

상태 카운트:

- 현재 페이지 기준 카운트는 그대로 유지.
- 전체 상태별 총량이 필요하면 추후 `/tasks/stats`를 추가한다. MVP에서는 현재 방식 유지.

## `TaskToolbar` 변경

props 추가:

- `scopeMode`
- `lockedAssigneeId?: string`
- `showAssigneeFilter?: boolean`

정책:

- 전체 업무: 담당자 필터 표시.
- 내 업무: 담당자 필터 숨김. 필요하면 disabled select로 “내 업무” 표시.
- 특정 사용자 업무: 담당자 필터 숨김 또는 disabled select로 대상 사용자 표시.

사용자 이동 UX:

- 전체 업무 toolbar에 `담당자` select는 현재처럼 필터로 유지한다.
- 특정 사용자 페이지로 직접 이동하는 UI가 필요하면 업무 관리 2차 메뉴 아래가 아니라 페이지 내부에 “담당자 보기” select를 추가하고 선택 시 `/task/users/{id}`로 navigate한다.

## `TaskFormDialog` 변경

props 추가:

- `defaultScope?: TaskScope`
- `currentUserId?: string`
- `lockAssigneeToCurrentUser?: boolean`

개인 업무 생성:

- 내 업무 페이지에서 새 업무를 누르면 기본 `scope=PERSONAL`.
- `assigneeId=currentUserId`.
- 담당자 select는 숨기거나 disabled 처리.

전체 업무 생성:

- 기본 `scope=TEAM`.
- 담당자 select 유지.

선택 UI:

- dialog 상단에 `팀 업무` / `개인 업무` segmented control을 둘 수 있다.
- 단, 내 업무 페이지에서는 개인 업무가 기본이고 팀 업무 전환은 필요할 때만 허용한다.

## 헤더 메뉴

`app-header.tsx` 변경:

- `sectionIdToPath()`:
  - `task_all: '/task'`
  - `task_my: '/task/my'`
- `getSectionIdFromPath()`:
  - `/task/my` -> `task_my`
  - `/task/users` -> `task_all` 또는 `task_my`가 아니라 parent active 처리를 위해 업무 계열 id 반환
  - `/task` -> `task_all`

`NavDropdown` active 판단은 child active를 이미 지원한다. parent 메뉴를 active로 표시하려면 child `sectionId`가 현재 active section과 매칭되면 된다.

모바일 메뉴도 같은 `menuTree`와 `onNavigate`를 쓰므로 section mapping만 맞으면 동작한다.
