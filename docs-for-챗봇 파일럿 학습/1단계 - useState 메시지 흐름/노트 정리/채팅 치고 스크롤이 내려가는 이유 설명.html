채팅 치고 스크롤이 내려가는 이유

1단계 노트 · scrollIntoView + overflow-y-auto 동작 원리

핵심 요약

"스크롤 내려라" 라고 명령하는 게 아니라,
"이 요소를 화면에 보이게 해라" 고 요청하는 것.
해당 요소가 화면 아래에 있으니까 브라우저가 알아서 아래로 스크롤한다.

1. scrollIntoView가 내려가는 이유

// 메시지 목록 맨 아래에 있는 빈 div
<div ref={bottomRef} />

// 메시지나 타이핑 상태가 바뀔 때마다 실행
useEffect(() => {
  bottomRef.current?.scrollIntoView({ behavior: "smooth" });
}, [messages, isTyping]);

bottomRef가 가리키는 빈 div는 메시지 목록 맨 아래에 있다.
새 메시지가 추가되면 이 div는 화면 밖 아래로 밀려난다.
그 상태에서 scrollIntoView()를 호출하면 브라우저는
"저 div를 보이려면 아래로 스크롤해야겠다" 고 판단해서 내려간다.

만약 bottomRef div가 이미 화면 안에 보이고 있으면 → 아무 일도 안 일어난다.
즉, 필요할 때만 스크롤한다.

Q. behavior: "smooth" 는 뭐야?

스크롤 이동 방식 옵션이다.
"smooth" — 부드럽게 애니메이션
"instant" — 즉시 이동 (기본값)

2. 의존성 배열에 messages와 isTyping이 둘 다 있는 이유

}, [messages, isTyping]);
messages — 새 메시지(내 말 or AI 응답)가 추가될 때 스크롤

isTyping — AI가 타이핑 중일 때 점 3개 인디케이터가 뜨는데,
              그것도 맨 아래에 있어야 하니까 true가 되는 순간에도 스크롤

만약 isTyping을 빼면? → 점 3개가 화면 밖으로 밀려나도 스크롤이 안 내려간다.

3. 스크롤 설정은 어디에 있나

// chatbot-basic-page.tsx 94번째 줄
<div className="ui-panel flex-1 overflow-y-auto rounded-lg p-4">

Q. overflow-y-auto 가 없으면?

메시지가 쌓일수록 채팅창이 아니라 페이지 전체가 길어진다.
scrollIntoView가 페이지 스크롤을 움직이게 되고, 헤더도 같이 스크롤된다.

Q. flex-1 이 없으면?

채팅창 높이가 고정되지 않아서 내용 크기에 따라 늘어난다.
overflow-y-auto가 발동하려면 컨테이너 높이가 고정돼 있어야 한다.
flex-1 + overflow-y-auto 이 두 개는 항상 함께 써야 한다.

4. 전체 흐름 정리

① 사용자가 Enter 입력
        ↓
② handleSend() 실행
   → setMessages([...prev, userMsg])   // messages 배열 변경
   → setIsTyping(true)                 // isTyping 변경
        ↓
③ useEffect 감지 (messages 또는 isTyping 바뀜)
   → bottomRef.current.scrollIntoView() 실행
        ↓
④ 브라우저: "bottomRef div가 화면 밖이네 → 아래로 스크롤"
        ↓
⑤ 새 메시지 + 타이핑 인디케이터가 화면에 보임
