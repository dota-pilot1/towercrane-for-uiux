Q. constructor(private configService: ConfigService)는 왜 필요한가?

NestJS의 의존성 주입(DI) 때문이다.
생성자에 선언하면 NestJS가 ConfigService 인스턴스를 자동으로 주입해준다.

// ❌ 직접 쓰면 .env 못 읽음
process.env.OPENAI_API_KEY

// ✅ ConfigService를 주입받아야 .env 값 읽기 가능
this.configService.get('OPENAI_API_KEY')
흐름:
app.module.ts → ConfigModule.forRoot() (.env 로드)
→ ChatbotService 생성 시 NestJS가 ConfigService 자동 주입
→ this.configService.get('OPENAI_API_KEY') 로 값 읽기

Q. openai.chat.completions.create()의 stream: true 가 뭔가?

stream 옵션동작
stream: false (기본)GPT가 다 생성할 때까지 기다렸다가 한 번에 반환. 사용자는 3~10초 대기 후 전체 텍스트가 한 번에 뜸
stream: true토큰 생성될 때마다 즉시 전달. 타이핑되듯 흘러나옴

청크가 한 글자씩이 아니라 불규칙한 이유: GPT는 토큰(의미 단위)으로 보내기 때문이다. "안", "녕하세요" 처럼 묶여서 오는 것이 정상이다.

Q. 처음에 @Sse를 썼다가 왜 @Post + @Res로 바꿨나?

SSE는 GET 프로토콜이라 JSON Body를 쓸 수 없다.
message를 query param으로 보내야 해서 한글 인코딩 문제 등 불편함이 있었다.
SSE (@Sse)스트리밍 Response (@Post + @Res)
HTTP 메서드GET만 가능POST 가능 ✅
Body못 씀 (query param만)JSON body 사용 가능 ✅
실무 사용알림, 피드AI 챗봇 스트리밍 ✅

ChatGPT, Claude 공식 API도 이 패턴을 사용한다.

Q. 스트리밍 Response 방식의 컨트롤러/서비스 구조가 뭔가?

// controller — @Res()로 응답 객체를 직접 받음
@Post('stream')
async stream(@Body() body: { message: string }, @Res() res: Response) {
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');
  await this.chatbotService.streamGpt(body.message, res);
}

// service — res.write()로 청크를 직접 흘려보냄
async streamGpt(message: string, res: Response) {
  const stream = await this.openai.chat.completions.create({
    stream: true, ...
  });

  for await (const chunk of stream) {
    const text = chunk.choices[0]?.delta?.content ?? '';
    if (text) {
      res.write(`data: ${JSON.stringify({ text })}\n\n`);
    }
  }

  res.write('data: [DONE]\n\n');
  res.end();
}
일반 REST: return { data } — NestJS가 JSON으로 변환해서 응답

스트리밍: res.write() — 응답 객체를 직접 제어해서 청크를 흘려보냄
            res.end() — 응답 종료

Q. 서버에서 [DONE] 보내고 res.end() 하면 끝인가?

서버                              프론트
  │                                 │
  ├─ data: {"text":"안녕"}  ───────► 텍스트 누적
  ├─ data: {"text":"하세요"} ──────► 텍스트 누적
  ├─ data: [DONE]          ───────► isStreaming = false
  └─ res.end() → 연결 종료

프론트에서 추가로 해야 할 것:

if (data === '[DONE]') {
  setIsStreaming(false)   // 커서 깜빡임 끄기, 전송버튼 활성화
  return
}
setMessages(prev =>
  prev.map(m => m.id === msgId
    ? { ...m, content: m.content + text }  // 텍스트 누적
    : m
  )
)

전체 흐름 정리

① 프론트: POST /api/chatbot/stream  { "message": "안녕하세요" }
        ↓
② Controller: @Body()로 message 추출, @Res()로 res 객체 확보
        ↓
③ Service: res 헤더 설정 (Content-Type: text/event-stream)
        ↓
④ OpenAI API: stream: true 로 요청
        ↓
⑤ GPT 토큰 생성될 때마다
   for await → res.write(`data: ${JSON.stringify({ text })}\n\n`)
        ↓
⑥ 루프 끝 → res.write('data: [DONE]\n\n') → res.end()
        ↓
⑦ 프론트: [DONE] 받으면 isStreaming = false → UI 정리
