2-1 FAQ — 백엔드 스트리밍 응답 API

2단계 노트 · NestJS + OpenAI SSE 스트리밍 구현 질문 정리

Q. constructor(private configService: ConfigService)는 왜 필요한가?

NestJS의 의존성 주입(DI) 때문이다.
ConfigService는 NestJS가 관리하는 서비스라 직접 new ConfigService()로 만들 수 없다.
생성자에 선언하면 NestJS가 알아서 인스턴스를 주입해준다.

// ❌ 직접 쓰면 .env 못 읽음
process.env.OPENAI_API_KEY

// ✅ ConfigService를 주입받아야 .env 값 읽기 가능
this.configService.get('OPENAI_API_KEY')
흐름:
app.module.ts → ConfigModule.forRoot() (.env 로드)
→ ChatbotService 생성 시 NestJS가 ConfigService 자동 주입
→ this.configService.get('OPENAI_API_KEY') 로 값 읽기

Q. openai.chat.completions.create() 코드는 무슨 의미인가?

OpenAI API에 스트리밍 요청을 보내는 코드다.

const stream = await this.openai.chat.completions.create({
  model: 'gpt-4o-mini',         // 어떤 GPT 모델을 쓸지
  stream: true,                 // 핵심 — false면 한 번에, true면 청크로
  messages: [
    { role: 'user', content: message }  // 사용자 메시지
  ],
});
stream 옵션동작
stream: false (기본)GPT가 다 생성할 때까지 기다렸다가 한 번에 반환. 3~10초 대기 후 전체 텍스트가 한 번에 뜸
stream: true토큰 생성될 때마다 즉시 전달. "안", "녕", "하", "세요" 타이핑되듯 흘러나옴

messages가 배열인 이유: 실제 대화에서는 이전 대화 내용도 같이 보내야 GPT가 맥락을 안다.

messages: [
  { role: 'system', content: '너는 친절한 상담사야' },
  { role: 'user', content: '안녕' },
  { role: 'assistant', content: '안녕하세요!' },
  { role: 'user', content: '오늘 날씨 어때?' },  // 지금 질문
]

Q. @Sse('stream')은 응답 타입인가?

맞다. @Sse는 응답 타입을 SSE로 선언하는 데코레이터다.

@Get()   → Content-Type: application/json
@Post()  → Content-Type: application/json
@Sse()   → Content-Type: text/event-stream  ← SSE 프로토콜

Q. 컨트롤러가 함수(Observable)를 반환하는 게 일반 REST API랑 다른데?

// 일반 REST — 값 반환 → 한 번에 응답 끝
@Get('user')
getUser() {
  return { name: '홍길동' }
}

// SSE — Observable 반환 → 스트림을 반환
@Sse('stream')
stream() {
  return this.chatbotService.streamGpt(...)
}
일반 REST → 값 반환 → 응답 끝

SSE → Observable(파이프) 반환 → NestJS가 Observable을 구독해서
        .next() 호출될 때마다 클라이언트로 전송
        .complete() 호출되면 연결 종료

Q. 파이프만 반환하면 끝인가? 스트리밍 끝에 뭔가 더 해야 하는 게 없나?

서버                         프론트
  │                            │
  ├─ { text: "안" }    ──────► 화면에 "안" 추가
  ├─ { text: "녕" }    ──────► 화면에 "녕" 추가
  ├─ { text: "하세요" }──────► 화면에 "하세요" 추가
  ├─ [DONE]            ──────► isStreaming = false
  └─ 연결 종료

추가로 해야 할 건 딱 하나 — 프론트에서 [DONE] 감지해서 상태 정리다.

if (data === '[DONE]') {
  setIsStreaming(false)   // 커서 깜빡임 끄기, 전송버튼 활성화
  return
}
// 아니면 텍스트 누적
setMessages(prev => ...)
.complete()만으로도 연결은 끊기지만,
프론트가 "스트리밍 끝났다"는 걸 명시적으로 알아야 UI 상태를 정리할 수 있어서
[DONE] 신호를 같이 보내는 것이 관례다.

Q. streamGpt() 함수 내부가 직관적이지 않은데, 이해해야 하나 외워야 하나?

패턴을 외워서 갖다 쓰는 코드다. subscriber.next()가 프론트로 전송된다는 게 코드만 봐서는 전혀 안 보인다.
NestJS + RxJS 내부에서 처리해주는 거라 연결고리가 숨겨져 있다.

이해해야 할 것외워서 쓰는 것
stream: true로 GPT가 청크를 줌new Observable((subscriber) => {}) 껍데기
for await로 청크를 하나씩 처리void (async () => {})() 패턴
[DONE]으로 프론트에 완료 신호subscriber.next() / .complete()
핵심만 기억하면 된다:

GPT 청크 → for await로 받음 → subscriber.next()로 흘려보냄

나머지 Observable 껍데기는 NestJS SSE가 요구하는 형식이라 틀로 복붙해서 쓰면 된다.
실제 업무에서도 이런 코드는 "동작 원리 이해" + "틀은 복붙" 조합으로 쓴다.

전체 흐름 한 번에 정리

① 프론트가 POST /chatbot/stream 요청
        ↓
② ChatbotController → chatbotService.streamGpt(message) 호출
        ↓
③ new Observable 생성 (파이프 준비)
        ↓
④ OpenAI API에 { stream: true } 로 요청
        ↓
⑤ GPT가 토큰 생성할 때마다
   for await 루프 → subscriber.next({ data: { text } })
   → 프론트로 즉시 전송
        ↓
⑥ 루프 끝 → subscriber.next({ data: '[DONE]' })
           → subscriber.complete() → 연결 종료
        ↓
⑦ 프론트: [DONE] 받으면 isStreaming = false → UI 정리
