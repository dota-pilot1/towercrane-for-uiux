3-1 — 세션 히스토리 기본 구조

3단계 노트 · useHistoryChat 핵심 패턴 정리

1. 모든 대화를 sessions 배열로 관리

const [sessions, setSessions] = useState<Session[]>([initialSession])
const [activeId, setActiveId] = useState<string>(initialSession.id)
sessions — 전체 대화 목록 (배열)
activeId — 지금 화면에 열려있는 대화가 어느 것인지

2단계의 messages[] 하나가 → 3단계에서 sessions[].messages[] 로 한 겹 깊어진 구조

2. 첫 세션은 자동 생성 — id도 자동 설정

function makeSession(): Session {
  return {
    id: Date.now().toString(),   ← 타임스탬프로 유일한 id 생성
    title: `새 대화 ${sessionCounter++}`,
    messages: [],
    createdAt: new Date(),
  }
}

// 하나만 만들어서 sessions와 activeId 둘 다 참조
const initialSession = makeSession()
const [sessions, setSessions] = useState([initialSession])
const [activeId, setActiveId] = useState(initialSession.id)
initialSession을 미리 변수에 담아두는 이유:
같은 객체를 sessions[0]과 activeId 두 군데서 참조하기 위해서다.
두 번 makeSession()을 호출하면 id가 달라질 수 있다.

3. Session 타입

export type Session = {
  id: string
  title: string
  messages: Message[]   ← 이 대화의 메시지 전체
  createdAt: Date
}
세션은 "대화 한 편"을 감싸는 껍데기다.
ChatGPT 왼쪽 사이드바에 쌓이는 항목 하나 = 세션 하나

4. 현재 대화 메시지 꺼내기

// activeId로 sessions에서 현재 대화를 찾는다
const activeSession = sessions.find((s) => s.id === activeId)!
const messages = activeSession.messages
인덱스가 아니라 id로 찾기 때문에
세션 순서가 바뀌거나 목록이 길어져도 항상 정확한 대화를 가리킨다.

5. 질의 전송 흐름 — 2단계와 구조 동일, 한 겹만 깊어짐

STEP 1 — 전송 순간: 유저 메시지 + 빈 껍데기 동시 추가
const assistantMsgId = (Date.now() + 1).toString()
const assistantMsg: Message = {
  id: assistantMsgId,
  role: 'assistant',
  content: '',             ← 빈 껍데기
  timestamp: new Date(),
}

setSessions((prev) =>
  prev.map((s) => {
    if (s.id !== currentActiveId) return s  ← 활성 세션만 수정
    return {
      ...s,
      messages: [...s.messages, userMsg, assistantMsg],
      title: s.messages.length === 0        ← 첫 메시지면 제목 자동 설정
        ? text.slice(0, 20) + (text.length > 20 ? '…' : '')
        : s.title,
    }
  })
)
STEP 2 — 청크 수신: 활성 세션의 해당 메시지에 누적
const res = await fetch('http://localhost:3000/api/chatbot/stream', { ... })
const reader = res.body!.getReader()
const decoder = new TextDecoder()

while (true) {
  const { done, value } = await reader.read()
  if (done) break

  const lines = decoder.decode(value).split('\n')
  for (const line of lines) {
    if (!line.startsWith('data: ')) continue
    const payload = line.slice(6).trim()
    if (payload === '[DONE]') { setIsStreaming(false); return }

    const { text: chunk } = JSON.parse(payload)
    setSessions((prev) =>
      prev.map((s) => {
        if (s.id !== currentActiveId) return s   ← 활성 세션만
        return {
          ...s,
          messages: s.messages.map((m) =>
            m.id === assistantMsgId              ← 그 메시지만
              ? { ...m, content: m.content + chunk }
              : m
          ),
        }
      })
    )
  }
}
2단계와 비교:

2단계3단계
setMessages(prev => prev.map(...))setSessions(prev => prev.map(s => { ...s, messages: s.messages.map(...) }))
메시지 하나 수정세션 찾기 → 그 안의 메시지 수정
패턴은 동일, 세션을 먼저 특정하는 한 겹이 추가된 것뿐이다.

전체 구조 한 눈에

sessions (배열)
  ├─ { id: '111', title: '안녕', messages: [...] }   ← 비활성 세션
  ├─ { id: '222', title: '질문', messages: [...] }   ← activeId = '222'
  └─ { id: '333', title: '새 대화', messages: [] }   ← 비활성 세션

activeSession = sessions.find(s => s.id === '222')
messages      = activeSession.messages               ← 화면에 표시

전송 클릭 → id:'222' 세션의 messages에 추가
청크 수신  → id:'222' 세션의 특정 메시지 content 누적
