3-1 — 세션 추가 · 삭제

3단계 노트 · addSession / deleteSession 패턴 정리

addSession — 새 대화 만들기

function addSession() {
  const s = makeSession()
  setSessions((prev) => [s, ...prev])  ← 목록 맨 앞에 추가
  setActiveId(s.id)                    ← 새 세션을 바로 활성화
  setInput('')                         ← 입력창 초기화
}
[s, ...prev] — 새 세션을 맨 앞에 놓는다.
최신 대화가 항상 사이드바 위에 보이게 하기 위해서다.

세션 생성과 동시에 activeId를 새 세션으로 바꾸기 때문에
버튼 클릭 즉시 빈 채팅창으로 전환된다. 
// 흐름
+ 버튼 클릭
  → makeSession() 으로 새 세션 생성
  → sessions 맨 앞에 추가
  → activeId = 새 세션 id
  → 화면: 빈 채팅창

deleteSession — 대화 삭제

function deleteSession(id: string) {
  setSessions((prev) => {
    const next = prev.filter((s) => s.id !== id)  ← id가 다른 것들만 남김 (= 해당 id 제외)

    if (next.length === 0) {                       ← 마지막 세션을 지웠다면
      const fresh = makeSession()
      setActiveId(fresh.id)
      return [fresh]                               ← 빈 세션 하나 자동 생성
    }

    if (activeId === id) setActiveId(next[0].id)  ← 지운 게 현재 세션이면 첫 번째로 이동
    return next
  })
}
삭제 시 세 가지 케이스를 처리한다:

케이스 1 — 비활성 세션 삭제
  → 그냥 배열에서 제거, 현재 화면 변화 없음

케이스 2 — 현재 활성 세션 삭제
  → 삭제 후 남은 목록의 첫 번째 세션으로 자동 전환

케이스 3 — 마지막 남은 세션 삭제
  → 빈 세션을 새로 만들어서 항상 최소 1개 유지
왜 마지막 세션은 삭제 불가(자동 생성) 인가?

activeSession이 항상 존재해야 채팅 UI가 렌더링된다.
세션이 0개가 되면 sessions.find(...)가 undefined를 반환하고
activeSession.messages에서 런타임 에러가 발생한다.
그래서 마지막 세션을 지워도 바로 빈 세션 하나를 자동 생성한다.

두 함수 비교

addSession()
  → makeSession() 호출
  → [새세션, ...기존목록]
  → activeId = 새 세션

deleteSession(id)
  → filter로 제거
  → 남은 게 없으면 makeSession() 호출
  → activeId가 지워진 id면 next[0].id 로 교체
두 함수 모두 makeSession()을 통해 세션을 만든다는 공통점이 있다.
addSession은 새 대화를 위해, deleteSession은 빈 목록 방지를 위해.
