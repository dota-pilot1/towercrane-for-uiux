세션 목록 · 메시지 조회 — 프론트와 백엔드 각각의 흐름

조회 작업 2가지

작업트리거조회 대상
① 세션 목록 조회페이지 진입 시 1회chat_sessions 전체
② 메시지 조회세션 클릭 시 (캐시 미스)chat_messages where sessionId
3-2 (localStorage)와의 결정적 차이:

새로고침해도, 브라우저 캐시 지워도, 다른 기기에서 접속해도 같은 데이터를 본다.

① 세션 목록 조회 — 페이지 진입 시

흐름 한눈에

페이지 마운트
  ↓
useHistoryChat() 호출
  ↓
useEffect → loaded === false 면 loadSessions() 실행
  ↓
fetch GET /chatbot/sessions
  ↓
백엔드: SELECT * FROM chat_sessions ORDER BY updated_at DESC
  ↓
프론트: DTO → Session 변환 → store에 저장
  ↓
세션이 0개면 새로 만들기 (POST /chatbot/sessions)
  ↓
첫 세션 자동 활성화 → loadMessages() 호출
[프론트] use-history-chat.ts → useEffect
useEffect(() => {
  if (!loaded) void loadSessions()   // 페이지 진입 시 한 번만
}, [loaded, loadSessions])
[프론트] chat-session-store.ts → loadSessions
loadSessions: async () => {
  const dtos = await apiRequest<SessionDto[]>('/chatbot/sessions')
  let sessions = dtos.map(toSession)            // DTO → Session 변환

  if (sessions.length === 0) {                       // 빈 상태면
    const fresh = await apiRequest<SessionDto>('/chatbot/sessions', {
      method: 'POST',
      body: JSON.stringify({}),
    })
    sessions = [toSession(fresh)]                    // 새 세션 자동 생성
  }

  set({ sessions, activeId: sessions[0].id, loaded: true })
  await get().loadMessages(sessions[0].id)           // 첫 세션 메시지도 로드
}
[백엔드] chatbot.service.ts → listSessions
@Get('sessions')
listSessions() {
  return this.chatbotService.listSessions()
}

listSessions() {
  return this.db
    .select()
    .from(chatSessionsTable)
    .orderBy(desc(chatSessionsTable.updatedAt))   // 최근 활동순
    .all()
}

DTO 변환 — Date 직렬화 처리

// 백엔드는 createdAt/updatedAt 을 ISO 문자열로 반환
type SessionDto = {
  id: string
  title: string
  createdAt: string     // "2026-05-24T05:18:13.000Z"
  updatedAt: string
}

// 프론트는 Date 객체로 사용
function toSession(s: SessionDto): Session {
  return {
    id: s.id,
    title: s.title,
    createdAt: new Date(s.createdAt),
    updatedAt: new Date(s.updatedAt),
  }
}
JSON은 Date를 직접 직렬화 못 한다 → 백엔드는 문자열로 반환, 프론트가 Date로 변환.
이걸 안 하면 message.timestamp.toLocaleTimeString() 같은 호출에서 에러.

② 메시지 조회 — 세션 클릭 시

흐름 한눈에

사용자가 사이드바에서 세션 클릭
  ↓
switchSession(id) 호출
  ↓
activeId 변경 + loadMessages(id) 호출
  ↓
캐시 있음? → 그냥 사용 (API 호출 X)
캐시 없음? → fetch GET /chatbot/sessions/:id/messages
  ↓
백엔드: SELECT * FROM chat_messages WHERE session_id = ? ORDER BY created_at ASC
  ↓
프론트: DTO → Message 변환 → messagesBySession[id] 에 캐시
[프론트] chat-session-store.ts → switchSession + loadMessages
switchSession: (id) => {
  set({ activeId: id })
  void get().loadMessages(id)
}

loadMessages: async (sessionId) => {
  const cached = get().messagesBySession[sessionId]
  if (cached) return                          // 캐시 있으면 스킵

  const dtos = await apiRequest<MessageDto[]>(
    `/chatbot/sessions/${sessionId}/messages`,
  )
  const messages = dtos.map(toMessage)
  set((state) => ({
    messagesBySession: {
      ...state.messagesBySession,
      [sessionId]: messages,                  // 세션별로 캐시
    },
  }))
}
[백엔드] chatbot.service.ts → listMessages
@Get('sessions/:id/messages')
listMessages(@Param('id') id: string) {
  return this.chatbotService.listMessages(id)
}

listMessages(sessionId: string) {
  return this.db
    .select()
    .from(chatMessagesTable)
    .where(eq(chatMessagesTable.sessionId, sessionId))
    .orderBy(asc(chatMessagesTable.createdAt))   // 오래된 것부터
    .all()
}

왜 캐시를 두는가

세션 전환할 때마다 API 호출하면 다음 문제가 생긴다:
  • 네트워크 왕복 시간만큼 빈 화면 보임
  • 서버 부하 증가
한번 받아온 메시지는 messagesBySession[id] 에 보관 →
같은 세션을 다시 클릭하면 즉시 표시.

Message DTO 변환

type MessageDto = {
  id: string
  sessionId: string
  role: 'user' | 'assistant'
  content: string
  createdAt: string          // 백엔드는 createdAt
}

function toMessage(m: MessageDto): Message {
  return {
    id: m.id,
    role: m.role,
    content: m.content,
    timestamp: new Date(m.createdAt)   // 프론트는 timestamp 필드명
  }
}
필드명 차이: 백엔드는 createdAt, 프론트는 기존 코드와의 호환을 위해 timestamp.
DTO 변환 함수가 그 차이를 흡수한다.

새로고침 시나리오 — 전체 흐름

[T+0]  사용자가 F5 누름
       ↓

       ↓

       ↓

       ↓
[T+50] GET /chatbot/sessions 응답
       → sessions: [{ id: '7f3a', title: '안녕', ... }, ...]
       ↓

       ↓
[T+60] loadMessages('7f3a') 호출
       ↓
[T+100] GET /chatbot/sessions/7f3a/messages 응답
        → messages: [{ id: '...', content: '안녕', ... }, ...]
       ↓
[T+110] set({ messagesBySession: { '7f3a': messages } })
       ↓

새로고침 → 100ms 정도면 이전 대화가 그대로 복원된다.
