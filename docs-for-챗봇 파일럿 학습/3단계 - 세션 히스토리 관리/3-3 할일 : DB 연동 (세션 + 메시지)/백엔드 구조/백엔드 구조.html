1. 테이블 구조

chat_sessions — 대화 세션

export const chatSessionsTable = sqliteTable('chat_sessions', {
  id: text('id').primaryKey(),
  title: text('title').notNull(),
  createdAt: text('created_at').notNull(),
  updatedAt: text('updated_at').notNull(),
})
컬럼타입설명
idTEXT PKUUID v4 — randomUUID() 로 생성
titleTEXT NOT NULL사이드바에 표시될 제목. 기본 "새 대화", 첫 메시지로 자동 변경
created_atTEXT NOT NULL생성 시각 (ISO 8601 문자열)
updated_atTEXT NOT NULL마지막 메시지 시각 — 정렬 기준

chat_messages — 메시지

export const chatMessagesTable = sqliteTable('chat_messages', {
  id: text('id').primaryKey(),
  sessionId: text('session_id').notNull()
    .references(() => chatSessionsTable.id, { onDelete: 'cascade' }),
  role: text('role').$type<'user' | 'assistant'>().notNull(),
  content: text('content').notNull(),
  createdAt: text('created_at').notNull(),
})
컬럼타입설명
idTEXT PKUUID v4
session_idTEXT FKchat_sessions(id) 참조. cascade 삭제
roleTEXT NOT NULL'user' 또는 'assistant'
contentTEXT NOT NULL메시지 본문. assistant는 스트리밍 누적 완성본
created_atTEXT NOT NULL생성 시각 — 정렬 기준 (오름차순)
onDelete: cascade 의 의미
세션을 삭제하면 해당 세션의 모든 메시지가 자동으로 함께 삭제된다.
애플리케이션 코드에서 메시지를 따로 지울 필요 없음.
SQLite에 PRAGMA foreign_keys = ON 설정이 되어있어야 동작.

관계도

chat_sessions (1)  ──< cascade >──  chat_messages (N)
  │                                       │
  ├─ id                                   ├─ id
  ├─ title                                ├─ session_id (FK)
  ├─ created_at                           ├─ role
  └─ updated_at                           ├─ content
                                          └─ created_at

PATCH/chatbot/sessions/:id

세션 이름 변경

renameSession(id: string, title: string) {
  const trimmed = title.trim()
  if (!trimmed) throw new NotFoundException('title is required')

  const now = new Date().toISOString()
  const result = this.db
    .update(chatSessionsTable)
    .set({ title: trimmed, updatedAt: now })   ← updated_at도 갱신
    .where(eq(chatSessionsTable.id, id))
    .run()

  if (result.changes === 0) {                    ← 존재하지 않는 id
    throw new NotFoundException('session not found')
  }
  return { id, title: trimmed, updatedAt: now }
}
result.changes 로 실제 업데이트된 행 수 확인.
0이면 해당 id 세션이 없는 것 → 404 반환.

POST/chatbot/stream

스트리밍 + 메시지 자동 저장 (핵심 API)

async streamGpt(sessionId: string, message: string, res: Response) {
  if (!this.openai) throw new ServiceUnavailableException(...)

  // ① 세션 갱신 + 첫 메시지면 title 자동 설정
  const meta = this.touchSession(sessionId, message)

  // ② user 메시지 DB 저장
  const userMessage = this.insertMessage(sessionId, 'user', message)

  // ③ meta 이벤트 전송 — 프론트가 temp id를 server id로 교체
  res.write(`data: ${JSON.stringify({
    type: 'meta',
    userMessage,
    sessionTitle: meta.title,
  })}\n\n`)

  // ④ OpenAI 스트리밍 시작
  const stream = await this.openai.chat.completions.create({
    model: '...', stream: true,
    messages: [{ role: 'user', content: message }],
  })

  let assistantContent = ''
  for await (const chunk of stream) {
    const text = chunk.choices[0]?.delta?.content ?? ''
    if (text) {
      assistantContent += text                  ← 누적
      res.write(`data: ${JSON.stringify({ text })}\n\n`)
    }
  }

  // ⑤ 완성된 assistant 메시지 DB 저장
  const assistantMessage = this.insertMessage(
    sessionId, 'assistant', assistantContent,
  )

  // ⑥ done 이벤트 + [DONE]
  res.write(`data: ${JSON.stringify({ type: 'done', assistantMessage })}\n\n`)
  res.write('data: [DONE]\n\n')
  res.end()
}

스트리밍 응답 — 3가지 이벤트 타입

이벤트시점페이로드프론트 처리
type: 'meta' 스트리밍 시작 직전 { userMessage, sessionTitle } user temp id → server id 교체, 사이드바 title 갱신
{ text } 스트리밍 중 (반복) 토큰 단위 텍스트 assistant temp id에 누적
type: 'done' 스트리밍 완료 { assistantMessage } assistant temp id → server id 교체
[DONE] 연결 종료 직전 (텍스트 그대로) isStreaming = false

3. 헬퍼 메소드 — touchSession / insertMessage

touchSession — 세션 시간 갱신 + 첫 메시지 title 자동 설정

private touchSession(sessionId: string, firstMessageText?: string) {
  const session = this.db.select().from(chatSessionsTable)
    .where(eq(chatSessionsTable.id, sessionId)).get()
  if (!session) throw new NotFoundException('session not found')

  const messageCount = this.db.select().from(chatMessagesTable)
    .where(eq(chatMessagesTable.sessionId, sessionId)).all().length

  // 메시지가 하나도 없고 + 기본 제목이면 → 첫 메시지로 갈아끼움
  const shouldUpdateTitle =
    messageCount === 0 && firstMessageText && session.title === '새 대화'
  const nextTitle = shouldUpdateTitle
    ? firstMessageText!.slice(0, 20) + (firstMessageText!.length > 20 ? '…' : '')
    : session.title

  this.db.update(chatSessionsTable)
    .set({ title: nextTitle, updatedAt: new Date().toISOString() })
    .where(eq(chatSessionsTable.id, sessionId))
    .run()

  return { title: nextTitle, updatedAt: ... }
}

insertMessage — 메시지 한 건 저장

private insertMessage(sessionId, role, content) {
  const message = {
    id: randomUUID(),
    sessionId,
    role,
    content,
    createdAt: new Date().toISOString(),
  }
  this.db.insert(chatMessagesTable).values(message).run()
  return message
}
두 메소드 모두 private — 외부에서 직접 호출할 일 없음.
스트리밍 로직에서만 내부적으로 사용한다.
