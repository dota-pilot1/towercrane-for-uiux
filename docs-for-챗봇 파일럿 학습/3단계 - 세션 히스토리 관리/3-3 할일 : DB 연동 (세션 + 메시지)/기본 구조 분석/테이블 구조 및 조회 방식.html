3-3 — 테이블 구조 및 조회 방식

DB → DTO → Store 변환 흐름 · 세션/메시지 조회 타이밍 · 캐시 패턴

📌 핵심 요약

① 조회는 메타 없음 — 응답에 진짜 id가 이미 들어있어서 교체 불필요
② 두 단계 조회 — 페이지 마운트 시 세션 목록, 세션 클릭 시 메시지 목록
③ 캐시 패턴 — 메시지는 한 번 불러오면 messagesBySession 에 저장, 재요청 없음
④ DTO 변환 — DB의 ISO 문자열 → 프론트의 Date 객체로 변환

1. 조회 API 2개

목적API정렬트리거
세션 목록 GET /chatbot/sessions updated_at DESC (최신 순) 페이지 마운트
메시지 목록 GET /chatbot/sessions/:id/messages created_at ASC (시간 순) 세션 선택 시
둘 다 일반 REST — 스트리밍 아님, 한 번에 JSON 배열로 응답한다.
메타 이벤트도 없다. 응답에 진짜 DB id가 이미 포함되어 있기 때문이다.

2. 백엔드 조회 로직

세션 목록 조회

// chatbot.service.ts
listSessions() {
  return this.db
    .select()
    .from(chatSessionsTable)
    .orderBy(desc(chatSessionsTable.updatedAt))   ← 최신 대화가 위로
    .all()
}
.all() — 결과 전부를 배열로 반환.
정렬 기준은 updated_at — 가장 최근에 대화한 세션이 목록 맨 위에 온다.

메시지 목록 조회

// chatbot.service.ts
listMessages(sessionId: string) {
  return this.db
    .select()
    .from(chatMessagesTable)
    .where(eq(chatMessagesTable.sessionId, sessionId))  ← 이 세션 것만
    .orderBy(asc(chatMessagesTable.createdAt))          ← 시간 오름차순
    .all()
}
.where(eq(...)) — 특정 세션 id에 속한 메시지만 필터.
정렬 기준은 created_at ASC — 대화가 위에서 아래로 시간순으로 보이게.

3. DB → DTO → Store 변환 흐름

DB는 모든 날짜를 ISO 문자열로 저장한다.
프론트 store는 날짜를 Date 객체로 다룬다.
그 중간에 DTO 변환 함수가 있다.

세션 변환 — toSession()

// chat-session-store.ts

// DB에서 오는 형태 (ISO 문자열)
type SessionDto = {
  id: string
  title: string
  createdAt: string    ← '2026-05-24T05:18:13.000Z'
  updatedAt: string
}

// store에서 사용하는 형태 (Date 객체)
type Session = {
  id: string
  title: string
  createdAt: Date     ← new Date('2026-05-24T...')
  updatedAt: Date
}

// 변환 함수
function toSession(s: SessionDto): Session {
  return {
    id: s.id,
    title: s.title,
    createdAt: new Date(s.createdAt),
    updatedAt: new Date(s.updatedAt),
  }
}

메시지 변환 — toMessage()

// chat-session-store.ts

// DB에서 오는 형태
type MessageDto = {
  id: string
  sessionId: string
  role: 'user' | 'assistant'
  content: string
  createdAt: string    ← ISO 문자열
}

// store Message 타입
type Message = {
  id: string
  role: 'user' | 'assistant'
  content: string
  timestamp: Date     ← Date 객체
}

// 변환 함수
function toMessage(m: MessageDto): Message {
  return {
    id: m.id,
    role: m.role,
    content: m.content,
    timestamp: new Date(m.createdAt),   ← createdAt → timestamp 이름도 바뀜
  }
}
두 가지 변환이 동시에 일어난다:
① 타입: string → Date
② 이름: createdAt → timestamp (MessageDto → Message)

sessionId 는 store Message에 없다 — store는 이미 세션별로 분리돼 있으니 불필요.

4. 컬럼 매핑 한눈에

세션

DB (chat_sessions)     →  SessionDto       →  Session (store)
────────────────────────────────────────────────────────────
id          : 'abc'    →  id      : 'abc'  →  id        : 'abc'
title       : '안녕'   →  title   : '안녕' →  title     : '안녕'
created_at  : 'ISO'    →  createdAt: 'ISO' →  createdAt : new Date(ISO)
updated_at  : 'ISO'    →  updatedAt: 'ISO' →  updatedAt : new Date(ISO)

메시지

DB (chat_messages)     →  MessageDto          →  Message (store)
────────────────────────────────────────────────────────────────
id          : '1'      →  id         : '1'    →  id        : '1'
session_id  : 'abc'    →  sessionId  : 'abc'  →  (제거됨)
role        : 'user'   →  role       : 'user' →  role      : 'user'
content     : '안녕'   →  content    : '안녕' →  content   : '안녕'
created_at  : 'ISO'    →  createdAt  : 'ISO'  →  timestamp : new Date(ISO)

5. 조회 트리거 — 언제 불러오나

세션 목록 — 페이지 마운트 시 1번

// use-history-chat.ts
useEffect(() => {
  if (!loaded) void loadSessions()   ← loaded 가 false 일 때만 실행
}, [loaded, loadSessions])
// chat-session-store.ts — loadSessions()
loadSessions: async () => {
  const dtos = await apiRequest<SessionDto[]>('/chatbot/sessions')
  let sessions = dtos.map(toSession)

  // 세션이 하나도 없으면 자동으로 새 세션 생성
  if (sessions.length === 0) {
    const fresh = await apiRequest<SessionDto>('/chatbot/sessions', {
      method: 'POST',
      body: JSON.stringify({}),
    })
    sessions = [toSession(fresh)]
  }

  set({ sessions, activeId: sessions[0].id, loaded: true })
  await get().loadMessages(sessions[0].id)   ← 첫 세션 메시지도 즉시 로드
}
  • loaded 플래그로 중복 호출 방지
  • 세션이 없으면 빈 화면 대신 자동 생성
  • 세션 목록 로드 완료 직후 첫 번째 세션의 메시지도 즉시 불러옴

메시지 목록 — 세션 클릭 시

// chat-session-store.ts — loadMessages()
loadMessages: async (sessionId) => {
  // 이미 불러온 세션이면 재요청 안 함
  const cached = get().messagesBySession[sessionId]
  if (cached) return

  const dtos = await apiRequest<MessageDto[]>(
    `/chatbot/sessions/${sessionId}/messages`,
  )
  const messages = dtos.map(toMessage)
  set((state) => ({
    messagesBySession: { ...state.messagesBySession, [sessionId]: messages },
  }))
}
캐시 패턴 핵심: messagesBySession[sessionId] 가 이미 있으면 즉시 return.
같은 세션을 여러 번 클릭해도 API 호출은 딱 1번만 발생한다.

6. 전체 조회 흐름 — 시간 순서

[페이지 진입]
       ↓
useEffect → !loaded → loadSessions()
       ↓
GET /chatbot/sessions
       ↓
[{ id, title, created_at, updated_at }, ...]   ← DB 응답 (ISO 문자열)
       ↓
dtos.map(toSession)    ← ISO string → Date 객체
       ↓
set({ sessions, activeId: sessions[0].id, loaded: true })
       ↓
loadMessages(sessions[0].id)   ← 첫 세션 메시지 즉시 로드
       ↓
GET /chatbot/sessions/{id}/messages
       ↓
[{ id, session_id, role, content, created_at }, ...]
       ↓
dtos.map(toMessage)    ← createdAt string → timestamp Date
       ↓
set({ messagesBySession: { [id]: messages } })
       ↓
[화면 렌더링 완료]

─────────────────────────────

[사용자가 다른 세션 클릭]
       ↓
switchSession(id) → set({ activeId: id })
       ↓
loadMessages(id)
       ↓
messagesBySession[id] 있음? → 캐시 히트 → return (API 호출 없음)
                  없음? → 캐시 미스 → GET /chatbot/sessions/{id}/messages

7. 캐시 히트 / 미스 구조

messagesBySession = {
  'abc-...': [ { id, role, content, timestamp }, ... ],   ← 이미 로드됨
  'def-...': [ ... ],                                     ← 이미 로드됨
  'xyz-...': undefined,                                   ← 아직 미로드
}
상황결과API 호출
abc 세션 클릭 (2번째) 캐시 히트 → 즉시 렌더 없음
xyz 세션 클릭 (처음) 캐시 미스 → API 요청 후 렌더 1회
페이지 새로고침 store 초기화 → 전체 재요청 세션 + 첫 메시지
주의: 이 캐시는 메모리 캐시다.
새로고침하면 store가 초기화되어 모두 사라지고 다시 DB에서 불러온다.
→ 3-3에서는 DB가 진실의 원천, 메모리 캐시는 빠른 렌더를 위한 보조.

8. 조회 vs 저장 비교

구분조회저장 (스트리밍)
API 형태 GET — JSON 한 방 POST — SSE 스트림
id 처리 응답에 진짜 id 포함 temp id → meta 이벤트로 교체
메타 이벤트 없음 있음 (type: 'meta', type: 'done')
DB 날짜 타입 ISO string → Date 변환 ISO string → Date 변환 (동일)
캐시 messagesBySession에 저장 appendLocalMessage로 즉시 추가

9. 정리

조회의 핵심 3가지:

① 세션 목록 — 페이지 마운트 1번, loaded 플래그로 중복 방지
② 메시지 목록 — 세션 클릭 시, 캐시 있으면 API 재호출 없음
③ DTO 변환 — DB ISO string → store Date 객체 (toSession, toMessage)
