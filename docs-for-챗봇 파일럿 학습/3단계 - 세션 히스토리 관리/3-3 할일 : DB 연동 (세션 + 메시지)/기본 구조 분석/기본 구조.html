2. Zustand persist (3-2) vs DB 연동 (3-3) 비교

항목 3-2 (persist + localStorage) 3-3 (DB 연동)
저장 위치 브라우저 localStorage 서버 SQLite DB
새로고침 후 유지 유지
브라우저 캐시 삭제 후 사라짐 유지
다른 기기에서 접속 안 보임 보임
다른 사람이 같은 PC로 로그인 대화 노출됨 (보안 문제) 유저별 분리 (3-4)
store 상태 sessions[] (messages 포함) sessions[] + messagesBySession{}
(분리 보관)
액션 동기 (set 호출) 비동기 (async + fetch)
persist 미들웨어 사용 제거 (DB가 원본)
Date 직렬화 처리 partialize + onRehydrateStorage DTO 변환 함수 (toSession, toMessage)

// 3-2
type ChatSessionState = {

  activeId: string
  addSession: () => void           // 동기
  deleteSession: (id) => void
  appendMessages: (...) => void
  updateAssistantChunk: (...) => void
}

// 3-3
type ChatSessionState = {
  sessions: Session[]              // title만
  activeId: string
  messagesBySession: Record<string, Message[]>  // 분리 보관
  loaded: boolean                              // 초기 로드 플래그

  loadSessions: () => Promise<void>          // 비동기
  loadMessages: (id) => Promise<void>
  addSession: () => Promise<void>
  deleteSession: (id) => Promise<void>

  // 스트리밍 중 로컬 갱신 (DB 저장은 서버가 함)
  appendLocalMessage: (...) => void
  updateLocalChunk: (...) => void
  replaceLocalMessage: (...) => void   // temp id → server id 교체
}
새로 생긴 핵심 개념:
  • messagesBySession — 세션 메타와 메시지 본문을 분리. 메시지는 진입 시점에 lazy load
  • loaded — 페이지 진입 시 1회만 API 호출하기 위한 가드
  • replaceLocalMessage — Optimistic UI에서 temp id를 server id로 갈아끼우기

4. 데이터 흐름 — 메시지 전송 시

① 사용자 입력
       ↓
② 프론트: temp id로 user + assistant 빈 껍데기를 store에 즉시 추가
       → 화면에 바로 표시됨 (Optimistic UI)
       ↓
③ 프론트: POST /chatbot/stream { sessionId, message }
       ↓
④ 서버: chat_messages 에 user 저장 + chat_sessions.updatedAt 갱신
       ↓
⑤ 서버: 첫 메시지면 title 자동 설정
       ↓
⑥ 서버: meta 이벤트 전송 { userMessage, sessionTitle }
       ↓
⑦ 프론트: temp user id → server id 교체, 사이드바 title 갱신
       ↓
⑧ 서버: OpenAI 스트리밍 시작 → 청크 전송 + 누적
       ↓
⑨ 프론트: 청크 받을 때마다 temp assistant id에 누적
       ↓
⑩ 서버: 완성된 assistant 메시지 chat_messages 에 저장
       ↓
⑪ 서버: done 이벤트 전송 { assistantMessage }
       ↓
⑫ 프론트: temp assistant id → server id 교체
       ↓
⑬ 서버: [DONE] 전송 → 연결 종료
핵심 패턴 — "먼저 보여주고 나중에 동기화":
서버 응답을 기다리는 동안 화면이 멈춰있지 않도록 temp id로 즉시 렌더링.
서버가 진짜 id를 돌려주면 그 자리만 살짝 교체.

5. 추가된 API 엔드포인트

메소드경로역할
GET/chatbot/sessions세션 목록 (최신순)
POST/chatbot/sessions새 세션 생성
PATCH/chatbot/sessions/:id이름 변경
DELETE/chatbot/sessions/:id삭제 (cascade로 메시지도 삭제)
GET/chatbot/sessions/:id/messages해당 세션 메시지 전체
POST/chatbot/stream스트리밍 + 메시지 자동 저장 (기존 API 확장)

전체 구조 한 눈에

chat_sessions (DB)              ← 영구 저장소
  ├─ id, title, createdAt, updatedAt
  └─ messages (1:N) → chat_messages
                        └─ id, sessionId, role, content, createdAt

       ↑↓ fetch (API)

chat-session-store (Zustand)    ← 화면용 캐시
  ├─ sessions: 메타만
  ├─ messagesBySession: 진입 시 lazy load
  └─ 모든 액션이 async + API 호출

       ↑↓ hook

use-history-chat                ← 스트리밍 청크 분기 처리
  ├─ meta 이벤트 → user temp id 교체
  ├─ text 청크 → assistant temp id에 누적
  └─ done 이벤트 → assistant temp id 교체
