3-3 — 메시지 캐시 방식 with Zustand

set()으로 저장 = 캐시 · 세션 id 키 구조 · 캐시 히트/미스 흐름

📌 두 줄 요약

① set() 으로 messagesBySession 에 넣는 순간 = 캐시에 저장
② 다음에 같은 세션 클릭 시 messagesBySession[id] 가 있으면 = 캐시 히트 → API 호출 없음

1. messagesBySession 구조

// Zustand store 초기 상태
messagesBySession: {}   ← 빈 객체. 아무 키도 없음.

// 세션 하나 불러온 후
messagesBySession: {
  'abc-...': [
    { id: '1', role: 'user',      content: '안녕',  timestamp: Date },
    { id: '2', role: 'assistant', content: '안녕!', timestamp: Date },
  ]
}

// 세션 두 개 불러온 후
messagesBySession: {
  'abc-...': [ 메시지들... ],
  'def-...': [ 메시지들... ],
  // 'xyz-...' 는 아직 클릭 안 해서 키 자체가 없음
}
세션 id가 키(key), 메시지 배열이 값(value).
키가 없으면 → 아직 캐시 없음.
키가 있으면 → 이미 불러온 것.

2. set() 호출 = 캐시에 저장하는 순간

// loadMessages() 내부
const dtos = await apiRequest(...)
const messages = dtos.map(toMessage)

set((state) => ({
  messagesBySession: {
    ...state.messagesBySession,      ← 기존 다른 세션 캐시 보존
    [sessionId]: messages,           ← 이 세션 id 키로 저장 = 캐시 저장
  },
}))

...state.messagesBySession 의 역할

// 기존 상태
messagesBySession: {
  'abc-...': [ 메시지들... ],    ← 이미 있는 것
}

// set() 호출 시 sessionId = 'def-...'
{
  ...state.messagesBySession,   ← 'abc-...' 캐시 그대로 복사
  ['def-...']: messages,         ← 새 세션 추가
}

// 결과
messagesBySession: {
  'abc-...': [ 메시지들... ],    ← 유지됨
  'def-...': [ 메시지들... ],    ← 새로 추가됨
}
스프레드(...)를 쓰는 이유:
Zustand의 set() 은 상태를 통째로 교체한다.
스프레드 없이 { [sessionId]: messages } 만 쓰면
기존 다른 세션 캐시가 모두 날아간다.

스프레드 없을 때 문제

// ❌ 잘못된 예 — 스프레드 없음
set(() => ({
  messagesBySession: {
    [sessionId]: messages,   ← 이것만 남고 나머지 다 사라짐
  },
}))

// 결과 — 'abc-...' 캐시가 날아감
messagesBySession: {
  'def-...': [ 메시지들... ],   ← 방금 것만 남음
}

// ✅ 올바른 예 — 스프레드 사용
set((state) => ({
  messagesBySession: {
    ...state.messagesBySession,  ← 기존 것 전부 복사
    [sessionId]: messages,       ← 새 것 추가
  },
}))

3. 캐시 확인 → 히트 / 미스

// loadMessages() 맨 앞
loadMessages: async (sessionId) => {
  const cached = get().messagesBySession[sessionId]
  if (cached) return   ← 캐시 히트: 바로 종료. API 호출 없음.

  // 캐시 미스: 여기서부터 실행
  const dtos = await apiRequest(...)
  ...
  set(...)   ← 캐시에 저장
}

캐시 히트 흐름

'abc-...' 세션 두 번째 클릭
       ↓
loadMessages('abc-...')
       ↓
get().messagesBySession['abc-...']
       = [ 메시지들... ]   ← 값 있음 (truthy)
       ↓
if (cached) return   ← 즉시 종료. API 호출 없음.

캐시 미스 흐름

'xyz-...' 세션 처음 클릭
       ↓
loadMessages('xyz-...')
       ↓
get().messagesBySession['xyz-...']
       = undefined   ← 값 없음 (falsy)
       ↓
if (cached) return   ← 통과
       ↓
GET /chatbot/sessions/xyz-.../messages   ← API 호출
       ↓
set({ messagesBySession: { ...기존, ['xyz-...']: messages } })
       ↓
캐시에 저장 완료   ← 다음번 클릭부터 히트

4. 전체 캐시 생명주기

[페이지 진입]
messagesBySession = {}   ← 비어있음
       ↓
loadSessions() → loadMessages(첫 세션 id)
       ↓
GET /messages → set()
messagesBySession = { 'abc-...': [...] }   ← 첫 세션 캐시 저장

[두 번째 세션 클릭]
       ↓
loadMessages('def-...')   ← 미스 → API 호출
messagesBySession = { 'abc-...': [...], 'def-...': [...] }

[첫 세션 다시 클릭]
       ↓
loadMessages('abc-...')   ← 히트 → return
messagesBySession = { 'abc-...': [...], 'def-...': [...] }   ← 변화 없음

[페이지 새로고침]
messagesBySession = {}   ← store 초기화 → 캐시 전부 사라짐
이 캐시는 메모리 캐시다.
새로고침하면 Zustand store가 초기화되어 모두 사라진다.
→ DB가 진실의 원천, 메모리 캐시는 같은 세션 반복 클릭 시 API 낭비를 막는 용도.

5. 정리

개념실제 코드역할
캐시 저장 set({ messagesBySession: { ...기존, [id]: messages } }) API 응답을 store 객체에 기록
캐시 확인 get().messagesBySession[sessionId] 키 있으면 히트, undefined면 미스
캐시 히트 if (cached) return API 호출 없이 즉시 종료
기존 캐시 보존 ...state.messagesBySession 다른 세션 캐시가 날아가지 않도록
캐시 초기화 페이지 새로고침 store 리셋 → 전부 사라짐
