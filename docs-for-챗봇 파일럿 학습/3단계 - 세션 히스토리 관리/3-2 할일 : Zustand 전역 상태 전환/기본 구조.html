3-2 — Zustand 기본 구조

3단계 노트 · 파일 구조 + useState vs Zustand 비교

1. 히스토리 챗 관련 파일 구조

features/chatbot/
  model/
    chat-session-store.ts    ← Zustand store (세션 상태 + 모든 액션)
    use-history-chat.ts      ← store 연결 + 스트리밍 로직 (여기서만 store 사용)
    use-chat-messages.ts     ← Message 타입 정의
  ui/
    chat-session-sidebar.tsx ← 사이드바 UI (props만 받음)
    chat-message.tsx         ← 메시지 말풍선
    chat-input.tsx           ← 입력창

pages/chatbot/ui/
  chatbot-history-page.tsx   ← 얇은 페이지 (useHistoryChat 호출만)
useChatSessionStore는 use-history-chat.ts 에서만 호출된다.
페이지나 UI 컴포넌트는 store를 직접 몰라도 된다.
hook이 store와 UI 사이의 유일한 연결 지점이다.

2. useState vs Zustand — 무엇이 어디로 이동했나

항목 3-1 useState 3-2 Zustand
sessions 상태 useState<Session[]>
hook 안에 존재		 store.sessions
전역 store에 존재
activeId 상태 useState<string>
hook 안에 존재		 store.activeId
전역 store에 존재
addSession setSessions([s, ...prev])
hook 안에 함수 정의		 store.addSession()
store 안에 액션 정의
deleteSession hook 안에 함수 정의 store 안에 액션 정의
메시지 추가 setSessions(prev => prev.map(...)) store.appendMessages(...)
청크 누적 setSessions(prev => prev.map(...)) store.updateAssistantChunk(...)
스트리밍 로직 hook 안에 존재 hook 안에 존재 (그대로)
input 상태 hook 안에 존재 hook 안에 존재 (그대로)
isStreaming 상태 hook 안에 존재 hook 안에 존재 (그대로)
페이지 이동 후 상태 사라짐 유지됨
새로고침 후 상태 사라짐 유지됨 (persist)
store로 이동한 것 — 세션 목록, 활성 id, 세션 관련 액션들
hook에 남은 것 — 스트리밍 로직, input, isStreaming

결국 "대화 데이터"는 store로, "현재 입력 중인 UI 상태"는 hook에 남은 구조다.
