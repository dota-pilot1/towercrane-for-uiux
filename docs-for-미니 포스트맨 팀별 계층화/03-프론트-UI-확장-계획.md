# 03. 프론트 UI 확장 계획

## 1차 화면 구조

첫 화면은 워크스페이스 카드 그리드로 둔다.

```text
┌─────────────────────────────────────────────────────────────┐
│ Postman Workspaces                                          │
│                                                             │
│ ┌────────────────┐ ┌────────────────┐ ┌────────────────┐   │
│ │ Prototype      │ │ AI 서비스 포털  │ │ 운영 Admin     │   │
│ │ Console        │ │ 팀              │ │ 팀             │   │
│ │ 6 collections  │ │ 4 collections  │ │ 3 collections  │   │
│ │ 24 requests    │ │ 18 requests    │ │ 11 requests    │   │
│ └────────────────┘ └────────────────┘ └────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

워크스페이스 카드를 클릭하면 해당 팀의 Postman Lite 화면으로 들어간다.

```text
/api-doc
  -> workspace cards

/api-doc?team={teamId}
  -> selected team Postman Lite
```

라우터를 바로 바꾸기 부담스러우면 1차에서는 내부 state로 처리한다.

```ts
const [selectedTeamId, setSelectedTeamId] = useState<string | null>(null)

if (!selectedTeamId) {
  return <ApiWorkspaceHome onOpenWorkspace={setSelectedTeamId} />
}

return <ApiDocWorkbench teamId={selectedTeamId} />
```

이 방식은 구현 난이도가 낮다. 현재 Postman 화면을 `ApiDocWorkbench` 성격으로 감싸고, 앞에 `ApiWorkspaceHome`만 하나 추가하면 된다.

## 1차 Postman 화면 구조

팀 워크스페이스를 최상위에 추가한다. 현재 3분할 구조는 유지한다.

```text
상단: 뒤로가기 / 현재 팀 / 환경 / import-export / 저장

┌──────────────┬─────────────────┬────────────────────────────┐
│ 컬렉션 목록   │ API 항목 목록      │ 요청 편집/테스트 패널        │
│              │                 │                            │
└──────────────┴─────────────────┴────────────────────────────┘
```

팀 전환은 처음에는 뒤로가기로 워크스페이스 홈에 돌아가서 선택한다. 필요하면 상단 title 영역에 팀 셀렉트를 추가한다.

```text
[← Workspaces]  Prototype Console / Postman Lite
```

이 방식은 현재 좌측 2컬럼 레이아웃을 크게 흔들지 않는다.

## 2차 화면 구조

폴더가 들어오면 좌측을 tree로 바꾼다.

```text
Team Workspace
  Collection Tree
    Folder
      Request
  Request Detail
```

데스크톱:

```text
팀/컬렉션 트리 | 요청 상세
```

또는 현재 구조를 유지하면서 2번째 컬럼을 tree로 바꾼다.

```text
컬렉션 목록 | 폴더 + 요청 트리 | 요청 상세
```

권장안은 후자다. 기존 UX 변화가 작다.

## 상태 설계

1차:

```ts
const [requestedTeamId, setRequestedTeamId] = useState<string | null>(null)
const selectedTeamId = ...
const selectedCategoryId = ...
const selectedEndpointId = ...
```

2차:

```ts
const [requestedFolderId, setRequestedFolderId] = useState<string | null>(null)
```

선택 우선순위:

1. 사용자가 직접 선택한 id가 현재 목록에 있으면 유지
2. 없으면 첫 번째 item 선택
3. 목록이 비면 null

현재 `ApiDocPage`의 category/endpoint 선택 방식과 같은 패턴을 재사용한다.

## 팀 선택 UX

관리자:

- 팀 생성
- 팀명 수정
- 팀 삭제
- 팀 정렬
- 팀별 컬렉션 생성
- 워크스페이스 카드에서 collection/request 개수 확인

일반 사용자:

- 접근 가능한 팀 목록 조회
- 워크스페이스 카드 선택
- 요청 Send

초기 권한 구현 전에는 일반 사용자에게 모든 팀을 보여줘도 된다. 팀 멤버 권한 도입 후 필터링한다.

## import/export UX

1차:

- 현재 선택된 팀 기준으로 내보내기
- 현재 선택된 팀에 가져오기

2차:

- 전체 팀 내보내기
- 선택 팀 내보내기
- 선택 컬렉션 내보내기

## 반응형

모바일은 한 화면에 3컬럼을 유지하지 않는다.

```text
1단계: 팀 선택
2단계: 컬렉션/요청 목록
3단계: 요청 상세
```

초기에는 데스크톱 우선으로 구현하고, 모바일은 기존 화면이 깨지지 않는 수준만 보장한다.
