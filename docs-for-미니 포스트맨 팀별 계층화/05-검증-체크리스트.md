# 05. 검증 체크리스트

## 백엔드 검증

- 서버 시작 시 `api_doc_teams`가 생성된다.
- 서버 시작 시 기존 `api_doc_categories`에 `team_id` 컬럼이 없으면 추가된다.
- 기존 category는 기본 팀에 자동 연결된다.
- `GET /api/api-doc/teams`가 팀 목록을 반환한다.
- `GET /api/api-doc/teams/:teamId/categories`가 해당 팀의 컬렉션만 반환한다.
- 팀 삭제 시 하위 컬렉션 삭제 정책을 명확히 따른다.
- 관리자 아닌 사용자가 편집 API를 호출할 때 기존 정책이 깨지지 않는다.

## 프론트 검증

- `/api-doc` 진입 시 워크스페이스 카드 목록이 먼저 보인다.
- 워크스페이스 카드에는 팀명, 설명, 컬렉션 수, 요청 수가 보인다.
- 워크스페이스 카드를 누르면 해당 팀의 Postman Lite 화면이 열린다.
- Postman Lite 화면에서 워크스페이스 홈으로 돌아갈 수 있다.
- 팀을 바꾸면 컬렉션 목록이 바뀐다.
- 팀을 바꿨을 때 이전 팀의 selected endpoint가 남아 요청 상세에 잘못 보이지 않는다.
- 컬렉션 추가 시 현재 선택된 팀 아래에 생성된다.
- 요청 저장 시 기존 `api_doc_blocks` 저장 형식이 유지된다.
- Send 버튼은 팀 구조와 무관하게 기존처럼 동작한다.
- 환경 변수 치환 `{{API_BASE}}`가 기존처럼 동작한다.

## import/export 검증

- 선택 팀 export 파일에 해당 팀의 컬렉션만 포함된다.
- version 1 import 파일을 선택 팀에 가져올 수 있다.
- version 2 import 파일을 가져올 수 있다.
- import 실패 시 일부 데이터만 들어가고 끝나는 문제가 없는지 확인한다.
- `lastResponse`는 import/export 대상에서 제외된다.

## 폴더 검증

- 폴더 없는 기존 요청이 "미분류"로 보인다.
- 폴더를 삭제할 때 하위 요청 처리 정책이 명확하다.
  - 권장 1안: 폴더 삭제 시 하위 요청도 삭제
  - 권장 2안: 폴더 삭제 시 하위 요청을 미분류로 이동
- 요청을 폴더 안에 만들 수 있다.
- 폴더별 정렬과 요청별 정렬이 서로 섞이지 않는다.

## 권한 검증

- owner는 팀 설정과 멤버 관리가 가능하다.
- editor는 컬렉션/폴더/요청 편집이 가능하다.
- viewer는 조회와 Send만 가능하다.
- 전역 admin은 모든 팀에 접근할 수 있다.
- 권한 없는 teamId로 API를 직접 호출해도 서버에서 차단된다.

7. Params/Header/Body 입력 후 저장
8. Send 실행
9. 다른 팀으로 전환
10. 방금 만든 컬렉션이 다른 팀에 보이지 않는지 확인

12. 선택 팀 export
13. 다른 팀에 import
14. import된 요청 Send 확인
